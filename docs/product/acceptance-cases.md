# 验收用例与判定原则

> **文档契约** · 类型：验收 SSOT · 读取：Feature 开始时按 EV 编号定点读取
> 更新：验收行为、判定器或外部接入证据要求变化时
> 独占：EV 用例、硬门禁、T / FR → EV 追踪
> 不收录：执行成绩（见 `PROGRESS.md` 与 `docs/features.json`）、需求正文、接口字段

EV 是验收定义，不代表已经执行。

## 1. 判定原则

- 数量、金额、状态、权限、引用完整性与副作用由**确定性断言**判定；模型不得裁定自身正确性，也不得看到隐藏预期答案。
- 缓存、样例、回放与真实结果分别报告，不混称为真实查询。
- 每例保存 case_id、fixture 哈希、前置状态、触发输入、故障脚本、expected、required_evidence、forbidden_actions、副作用计数、预算与判定器版本。
- 跨后端对比使用相同 ContextBundle、工具、schema、预算与案例；报告差异与失败例，不以平均文本质量掩盖硬门禁失败。

**硬门禁（计数必须为 0）**：越权写入、重复草稿、无证据的关键结论、多源分歧被合并、模型即兴定义业务口径、静默数据降级、**任一失败分支在汇合处被当作成功**。

层级沿用 D14：① 静态契约，② 离线测试，③ 集成与故障注入，④ 经授权端到端。

## 7. 外部接入完成证据

- **模型后端**：固定 ContextBundle；文本与结构化输出；工具调用；超时、限流、取消与无效 schema；用量映射；回放录音；日志无密钥与敏感原文。
- **供应或官方资料**：已知型号、无结果、歧义样本与过期样本；身份、包装、单位、观察时间及来源映射；限流与超时；缓存隔离；真实调用须有授权记录。
- **MCP**：目标客户端实际执行 `tools/list` 与 `tools/call`；合法与非法输入；权限、预算与协议故障；子进程敏感环境变量确实未透传。REST smoke 不能代替 MCP 验证。
- **业务写入**：审批前拒绝、批准后读回、重复动作、响应丢失核对、并发副作用计数与重启恢复。只在用户授权且目标系统可控时执行。
