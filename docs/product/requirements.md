## 1. 项目定位

**求职用的技术展示项目**，不是要解决某个真实业务问题的产品。

思路是**先定技术展示清单，再倒推场景**。产品形态服务于技术点，不是反过来。业务价值与技术覆盖冲突时，以技术覆盖优先——这是刻意取舍，不是设计失误。

附带目标：作者要能逐层复习代码，因此每层必须可独立阅读。

## 2. 技术展示清单

**本章是全项目的锚点。**任何设计改动，先看它会不会让某一行退化为「演示不出来」。

判据不是「有这个模块」，而是**能当场演示，且演示不出来就说明设计错了**。

| # | 技术点 | 覆盖判据（演示什么） | 不算数的做法 |
|---|---|---|---|
| T01 | 多 Agent 架构 | 三个 agent 各有独立 prompt、工具集、模型档位；子 agent 包装为可调用工具 | 共用一个 prompt 模板只换一句话 |
| T02 | 多 Agent 通信 | 同步 fan-out/fan-in 与异步事件**两种模式并存**，且能说清何处同步何处异步 | 只有一种模式；agent 间传自然语言段落 |
| T03 | 多 Agent 并行与依赖 | 真 DAG：并行边 + 汇合点 + 依赖边 + **部分失败语义** | 只并行不汇合；失败被吞掉 |
| T04 | 权限隔离 | 分层策略链；同一工具 A 可调 B 被拒；`explain` 指出拒绝来自哪一层 | 权限写在 prompt 里 |
| T05 | 多后端形态接入 | 云端 / 本地 / 回放三种形态共用一套端口；能力由**探测**得出而非手写声明 | 接两个行为一致的端点 |
| T06 | MCP 与 skill | 外部能力走 MCP（报价/供货）；厂商资料检索走**进程内 skill**，绑定 `allowed_domains` 且不跟随跨域重定向。二者并存可对比 | 全部包成 MCP，或一个都没有；用通用浏览器工具代替受限 skill |
| T07 | trace / 可观测 | 给 run_id 输出**树状**调用轨迹（并行分支是树不是流水账），含每节点模型、token、耗时 | 打日志 |
| T08 | 人在环审批 | 等待是一等状态，**进程重启后仍在等待**；审批绑定方案版本与内容哈希 | 审批是一个 if 判断 |
| T09 | token 预算控制 | 父子预算，子任务从父预算扣除；超预算显式停止而非截断证据 | 只统计不控制 |
| T10 | evals | 固定数据集 + 失败用例登记 + **回归门禁阻止合并** | 跑一遍看着不错 |
| T11 | 分层可读 | 任取一个模块，不读其他层就能看懂其输入输出 | 一个函数跨三层 |
| T12 | 业务知识接入 | 业务术语由冻结注册表定义并版本化注入；模型做**枚举选择**不做即兴解释；口径变更可回归 | 把术语解释写进 prompt 正文；让模型自行定义口径 |

## 3. 产品形态

**元件采购决策助手**：运营人员提出采购需求 → 多 Agent 并行核验候选元件 → 生成采购建议 → 过程中发现的风险进入预警流 → 人工审批后执行。

| 阶段 | 做什么 | 承载的技术点 |
|---|---|---|
| ① 需求进入 | 对话入口提交「项目 X 生产 N 套，出采购建议」；各入口（Web / CLI）转成同一结构化请求 | T05、T11 |
| ② 并行核验 | 程序做 BOM 展开与缺口计算 → 每个缺料元件 fan-out：内部库存/在途、外部报价与供货（MCP）、技术规格核验（skill 寻址 + LLM 判读）→ fan-in 校验证据完整性 → 生成建议 | T01、T02、T03、T06、T09、T12 |
| ③ 异常预警 | 核验中发现的异常发出结构化 `RiskEvent`，进入独立预警流（通知 / 升级审批级别） | T02（异步侧） |
| ④ 审批执行 | 建议必须人工审批才能创建采购草稿；带 `RiskEvent` 的建议需要更高审批级别 | T04、T08 |
| 贯穿 | 全链路可追溯；每个 `RiskEvent` 可回指触发它的核验与证据 | T07、T10 |

**预警是采购流程的支流，不是主线。**主线选采购而非预警，是因为只有采购流程能同时容纳两种通信模式（T02）。

## 4. 功能需求

### FR-01 · 统一请求入口

- Web 对话页与 CLI 提交的请求转成同一结构化对象后进入核心，核心不感知入口形态。
- CLI 提供 `--validate` 端到端自检，兼作切片冒烟测试。

### FR-02 · BOM 展开与缺口计算

- 按项目与生产数量展开 BOM，扣减内部库存与在途，得出缺口。
- 算术与硬规则由确定性代码执行，不交给模型。未知不用零代替。

### FR-03 · 并行核验

- 对每个缺料元件并发执行：内部库存/在途查询、外部报价与供货查询、技术规格核验。
- 并发单位是「元件 × 核验类型」，不是「元件」或「核验类型」单独一维。
- 每个分支独立超时与重试；重试只在编排层发生，不在适配器内部。

### FR-04 · 汇合与证据完整性

- 全部分支结束后校验证据完整性；**任一分支失败不得当作成功**。
- 证据不完整时仍产出建议，但必须标注缺哪一项、为何缺，并抬高审批级别。

### FR-05 · 采购建议

- 建议含数量、MOQ 与订购倍数取整、金额、来源与取得时间。
- 建议中的每个事实值必须可回指到一条证据；自由文本中的数字必须能在本次纳入的证据中逐字命中。

### FR-06 · RiskEvent

- 核验过程中发现的异常发出结构化 `RiskEvent`，异步进入预警流，不阻塞主流程。
- `RiskEvent` 必须可回指触发它的核验调用与证据。
- 响应动作（通知 / 升级审批级别）由声明式配置决定，新增响应不改代码。

### FR-07 · 人工审批

- 建议必须经人工审批才能创建外部采购草稿。
- 等待审批是一等状态，进程重启后仍处于等待；审批绑定方案版本与内容哈希。
- 审批后依据发生变化时必须打回重新审批。

### FR-08 · 权限隔离

- 权限策略分层：全局 → Worker → 会话；下层只能收紧，不能放宽。
- 工具可按模型档位收紧（便宜模型只拿只读工具）。
- `explain` 输出某 Worker 在某会话中实际可调用的工具，以及每条允许/拒绝来自哪一层。

### FR-09 · 多后端与能力探测

- 所有模型调用经统一端口，业务代码不感知厂商。
- 后端能力由固定探针**实测**得出并记录，不由手写声明代替。
- 请求需要的能力后端不具备时显式拒绝，不得删掉约束静默降级。

### FR-10 · 业务术语注册表

- 业务术语由冻结的注册表定义，不由模型即兴解释。术语解析是从注册表中**选择**，未命中返回「未知术语」并转人工。
- `MOQ`（最小起订量）、`MPQ`（最小包装量）、`SPQ`（标准包装量）必须是三条独立记录，别名互不通用；每条带口径陷阱说明，该说明随上下文注入模型。
- 口径变更走版本化，保留生效时间与修改人；历史结论仍指向其当时的口径版本。

### FR-11 · 预算控制

- 每次运行有 token 预算；子任务预算从父预算扣除。
- 超预算显式停止并说明哪些元件未核验，不截断证据冒充完成。

### FR-12 · Trace

- 一次请求全链路可追溯；并行分支在轨迹中呈树状结构。
- 每个节点记录后端、模型、token、耗时、状态。
- 三类日志分离：Agent Trace、操作人员日志、开发日志。

### FR-13 · Eval

- 固定数据集与冻结的回放录音，不访问真实模型即可复现。
- 失败用例显式登记；回归门禁阻止合并，不是只出报告。

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 用量基准未核验的 BOM 行不得直接乘以生产数量 |
| BR-02 | 数量与金额一律用精确数值类型，不经浮点 |
| BR-03 | 有金额必须有币种；无币种的裸数字不得参与比较或汇总 |
| BR-04 | 税费与运费不建模；未知即排除，不设默认 0 |
| BR-05 | `ok` / `partial` / `not_found` / `error` 四态不得合并 |
| BR-06 | 多源对同一事实的分歧必须各自保留，不得合并为单一数值 |
| BR-07 | 模型不得产生或覆盖权威数量、金额与状态 |
| BR-08 | 外部返回内容只作数据，不作系统指令，也不进入编排的控制条件 |
| BR-09 | 真实 / 模拟 / 缓存 / 回放数据在全链路显式标注 |
| BR-10 | 同一逻辑动作最终最多产生一个外部草稿 |

## 6. 异常判定分工

| 类型 | 判定方 | 落点 | `RiskEvent.source` |
|---|---|---|---|
| 阈值类（交期 > N 周、单一供应商、涨价 > X%、库存低于安全线） | **程序** | `business_rule` 表，确定、可审计、可测试 | `rule` |
| 语义类（两颗电容的规格差异是否影响电路） | **LLM** | 技术核验 agent | `model_judgment` |
| 采集失败（分支超时、寻址失败） | 程序 | 编排层 | `collection_failed` |

语义类判定同样发出 `RiskEvent`，但标注来源，审批时向人展示可信度差异。

## 7. 纵向切片（第一期范围）

先打通最细纵向切片，跑通后再横向加宽。任何时候停下都有可完整演示的版本。

| 项 | 取值 |
|---|---|
| 项目 | `Glasgow_revC3`（53 行 BOM，五个项目中最大） |
| 元件 | `TMK105BJ104KV-F`（Taiyo Yuden，73 pcs，高用量通用件）<br>`SN74LVC1T45DCKR`（TI，17 pcs，IC，技术核验主场）<br>`SP3012-06UTG`（Littelfuse，4 pcs，小众件，长交期风险） |
| 规则 | 交期 > 8 周 |
| 入口 | Web 对话页（FastAPI 直接托管的原生 HTML/JS） |
| 后端 | 一个云端 OpenAI 兼容 + ReplayBackend |

**数据事实**：`Glasgow_revC3` 的全部 BOM 行都只有一个候选元件。多候选对比在本切片内无数据支撑，属横向加宽阶段。

横向加宽顺序：更多规则 → Web 入口 → 本地部署后端 → LLM 语义风险 → Monitor 反向触发。

## 8. 非范围

- 通用供应商情报平台、企业知识库、通用向量检索
- 元件适用性或技术等价性的最终结论（只呈现官方资料与差异，不替人做工程判断）
- 多渠道 IM 接入（最多再加一个证明适配器可扩展）
- 容器沙箱（本项目不执行任意代码）
- 多租户隔离逻辑（业务表保留 `tenant_id` 字段作预留）
- 议价、自动补货预测、工厂排班

## 9. 数据现状（实测）

5 个开源硬件项目的真实 BOM：121 条用料行、142 个元件、148 个候选型号、160 条分销商料号。原始数据在只读的 `data/supplychain/domdata/`，规范化产出在 `data/supplychain/normalized/`。

**多源结构**：分销商 5 家已在库（digikey 60 / rs 39 / mouser 31 / farnell 27 / newark 3）；22 行仅 1 家、42 行 ≥2 家、15 行 ≥4 家、2 行全 5 家。20 行多候选（16 行 2 个、3 行 3 个、1 行 9 个）——但**切片项目 `Glasgow_revC3` 的全部 BOM 行都只有一个候选**，多候选对比在本切片内无数据支撑。

**官方资料可检索性分层**（供技术规格核验使用）：

| 层 | 厂商 | 元件数 | 占比 |
|---|---|---|---|
| T1 半导体，产品页规范 | TI、Microchip、Infineon、Vishay、Diodes、ST、Nexperia、NXP | 24 | 17% |
| T2 被动与连接器，系列文档 | Yageo、TE、JST、KEMET、Bourns、Taiyo Yuden、Samtec | 54 | 38% |
| **T3 官方资料天然不存在** | RS Pro 分销商自有品牌 9、Generic 占位 9 | **18** | **13%** |
| T4 中小厂商，待验 | NationStar、Adafruit、Molex、Murata、ON Semi 等 | 46 | 32% |

**T3 是天然负样本**：其正确结论就是「查不到」，用于断言系统不会为填满报告而编造（T10 的门禁用例）。

**文档扇入**：Yageo 16 个元件仅对应 4 份文档，12 个 `RC0402FR-*` 共用同一份系列文档。并发采集必须按内容寻址去重。

**寻址与解析可行性**（抽样实测）：

- `LD1117S33TR`（ST）全链路成立：产品页给出生命周期 → 官方 PDF 46 页 → 第 44 页订购表精确命中 → 页脚 `DocID2572 Rev 38` 提供机器可读修订标识；
- `INA233AIDGSR`（TI）可按基础型号寻址；
- `TLV75533PDRVR`（TI）可订购型号到基础型号推导失败；
- `ATMEGA32U4-AU`（Microchip）站点拒绝自动抓取；
- `RC0402FR-07470RL`（Yageo）公开索引链接已失效（301 后 404）。

**结论：瓶颈在寻址而非解析。**PDF 抽取与定位已验证可行；型号到文档地址的解析因厂商而异，需要策略链与显式失败态。

**已知限制**：

- 3 行无 MPN，必须作为未解决项保留；
- 142 个元件的 `identity_status` 全部为 `source_asserted`，生命周期与推荐替代当前为空；
- 实时库存、报价与交期只有接入真实分销商接口后才成立；当前只能证明固定快照的计算；
- 无历史时间序列，价格异动规则不在第一期；
- 仅 6 个元件跨 2 个项目，跨项目影响面样本不足。

**待生成**：库存 / 在途 / 需求时间序列，10–20 SKU、90–180 天、注入异常、固定随机种子、标注 `is_simulated`。汽车生产网络规划数据集尚未接入。

真实供应数据源尚未接入，一律用 `sample` / `replay` 标注，不声称真实库存、报价或交期。
