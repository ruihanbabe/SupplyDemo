## Q-01 · 首个真实供应数据源与凭据

**待定**：`sourcing` Worker 接入的第一个真实分销/报价源是哪一个，凭据如何取得。原 DigiKey 凭据已失效。

**当前对策**：用 `sample` / `replay` 标注的数据打通全链路，不声称真实库存、报价或交期。

**冻结条件**：凭据到位 + 字段映射校准样本 + 一次授权的只读调用证据。

## Q-03 · 外部采购草稿的目标系统与其幂等能力

**待定**：`action` Worker 写到哪个系统，该系统是否支持按 `logical_action_id` 查重。

**当前对策**：只生成内部方案，外部写入工具声明但不可用，相关端点返回 501。

**冻结条件**：目标系统确定 + 草稿字段映射 + 可验证的重复写入与「结果未知」故障注入。在此之前不得声称 exactly-once。

## Q-04 · 官方资料的寻址策略与许可边界

**待定**：

1. 寻址策略链的优先级与放弃条件（厂商 URL 模板 / 文档缓存 / 分销商返回的 datasheet 链接 / 厂商站内搜索）；
2. 抓取礼节：速率上限、`robots.txt` 遵守范围、缓存保留期；
3. 文档原文的留存许可边界。

已实测事实见 `docs/product/requirements.md` §9，此处不复制。要点：瓶颈在寻址而非解析；厂商间差异显著，存在站点拒绝抓取与公开索引失效的情况。

**当前对策**：只对可公开访问且明确允许下载的资料取证；缓存本地化并用于回放；无法寻址时输出显式失败态，不绕道第三方镜像站。

**冻结条件**：策略链顺序与放弃条件确定 + 速率与保留期确定 + 许可边界确认。

## Q-05 · 阈值取值与生命周期枚举映射

分工已由 D20 冻结（阈值归程序、进 `business_rule`）。**本条待定的是取值本身**：

1. 各条阈值规则的具体数值与分级（第一期只有「交期 > 8 周」，取值已定，其余未定）；
2. 生命周期阶段的枚举取值，以及各厂商原文表述到该枚举的映射。

厂商表述不统一是实测事实：ST 用 `Active - Product is in volume production`，TI 用 `ACTIVE`，其他厂商另有 NRND / Last Time Buy / Obsolete / Mature 等说法。映射表本身就是需冻结的契约，且必须保留原文而非只存归一化值。

**当前对策**：证据保存原文表述与定位，不强行归一化；`RiskEvent` 只输出事实型标签，不生成综合评分。

**冻结条件**：取值与映射表由用户确认，且每个厂商的映射有对应验收用例。

## Q-06 · Monitor 巡检的触发源与去重窗口（第二期）

D21 已定 Monitor 属第二期。**待定**：巡检周期、去重窗口时长、连续失败的退避、通知渠道。

**当前对策**：第一期不实现 Monitor，`RiskEvent` 只来自采购核验过程。

**冻结条件**：第一期跑通后再议。

## Q-07 · Web 入口的技术栈与首屏形态

第一期入口已定为 CLI（`requirements.md` §7），**待定的是 Web 那一侧**：技术栈、首屏信息密度与分组方式。

现有的对话页面（FastAPI 直接托管的原生 HTML/JS）只服务于对话入口的验证，不构成本项冻结。

**当前对策**：只做 CLI；Web 不开工。

**冻结条件**：用户确认技术栈与首屏形态。

## Q-08 · 认证、角色与证据原文访问权限

**待定**：认证方式、角色划分，以及谁可以看到证据原文与未脱敏 payload。

**当前对策**：单用户本地运行；证据原文默认不进入模型上下文与事件流，只保留脱敏摘要、哈希和引用。

**冻结条件**：角色模型确定 + 脱敏策略确定。
