## Q-01 · 首个真实供应数据源与凭据

**待定**：MVP 接入的第一个真实分销/供应数据源是哪一个，凭据如何取得。原 DigiKey 凭据已失效。

**当前对策**：使用 `sample` / `replay` provenance 的数据，全链路显式标注，不声称真实库存、报价或交期。

**冻结条件**：凭据到位 + 字段映射校准样本 + 一次授权的只读调用证据。

## Q-02 · 第二个真实模型后端

**待定**：第二个真实后端选哪一个。

**计数口径（已冻结，勿再改写）**：`ReplayBackend` 不计入真实后端；GLM（OpenAI-compatible）为**真实后端 #1**；待定的是**真实后端 #2，且必须走非 OpenAI-compatible 的原生协议**。

**当前对策**：先实现 `ModelBackend` 统一契约 + `ReplayBackend`，把能力协商和契约测试做完。

**冻结条件**：接入后能在同一组 fixture 上与后端 #1 跑通同一套契约测试，业务硬门禁独立断言通过。

> 追加一个 OpenAI-compatible endpoint **不满足**本项：endpoint 数量不等于多后端能力。

## Q-03 · 外部采购草稿目标系统与其幂等能力

**待定**：外部写入落到哪个系统，该系统是否支持按 `logical_action_id` 查重。

**当前对策**：只生成内部方案，`create_procurement_draft` / `reconcile_procurement_draft` 保持 `deferred`，相关端点返回 501。

**冻结条件**：目标系统确定 + 草稿字段映射 + 可验证的重复写入与结果未知故障注入。不得在此之前声称 exactly-once。

## Q-04 · 官方资料来源、寻址策略与许可边界

**已不再是延后项**：停产告警是 MVP 核心（`productinfo.md` §5.1），其证据只能来自制造商官方资料。本条待定的是策略与边界，不是要不要做。

**待定**：

1. 寻址策略链的优先级与放弃条件（厂商 URL 模板 / 文档缓存 / 分销商接口返回的 datasheet 链接 / 厂商站内搜索）；
2. 抓取礼节：速率上限、`robots.txt` 遵守范围、缓存保留期；
3. 文档原文的留存许可边界与可分发范围。

**已实测事实**见 `productinfo.md` §9.2、§9.3，此处不复制。要点：瓶颈在寻址而非解析；厂商间差异显著，存在站点拒绝自动抓取与公开索引链接失效的情况。

**当前对策**：只对可公开访问且明确允许下载的资料取证；缓存本地化并用于回放；无法寻址时输出 `unresolvable`，不绕道第三方镜像站。

**冻结条件**：策略链顺序与放弃条件确定 + 速率与保留期确定 + 许可边界确认。

## Q-05 · 告警分级与阈值

**待定**：

1. 库存告急的阈值口径（按绝对缺口 / 按覆盖天数 / 按需求日期前可用率）与分级；
2. 生命周期阶段的枚举取值，以及各厂商原文表述到该枚举的映射；
3. 是否有任何一级触发阻断，还是全部仅提示。

厂商表述不统一是实测事实：ST 用 "Active - Product is in volume production"，TI 用 "ACTIVE"，其他厂商另有 NRND / Not Recommended for New Designs / Last Time Buy / Obsolete / Mature 等说法。映射表本身就是需冻结的契约，且必须保留原文而非只存归一化值。

**当前对策**：Evidence 保存原文表述与定位，不强行归一化；告警只输出事实型标签，不生成综合评分，不自动阻断。

**冻结条件**：阈值口径、枚举与映射表由用户确认，且每个厂商的映射有对应验收用例。阈值一旦确定进入 `business_rule` 版本化配置，不写进 prompt 或节点。

## Q-06 · 事件触发与去重窗口

**已不再是延后项**：事件触发是 MVP 的主入口（`productinfo.md` §1、FR-08）。**不做定时巡检**——触发源限于用户提交的业务事件。

**待定**：哪些业务事件构成触发源（提交 BOM / 更新需求 / 导入库存快照）、去重窗口时长、连续失败的退避与告警阈值、通知渠道。

**当前对策**：只支持人工或 API 显式创建 Run；去重窗口语义已在 FR-08 与 BR-15 冻结（窗口内不创建第二个 Run，新触发并入既有 Run 或显式丢弃并留痕），待定的只是窗口时长与频率。

**冻结条件**：触发源集合与窗口时长确定，且有 EV-47 对应的验收证据。事件入口必须复用同一状态机、权限与证据要求。

## Q-07 · UI 技术栈与首屏形态

**待定**：Web 技术栈；告警列表作为首屏的信息密度与分组方式；是否需要桌面壳。

**当前对策**：只维护 `docs/spec/ui-contract.md` 的行为契约，不开始 UI 实现。

**冻结条件**：用户确认技术栈与首屏形态。

## Q-08 · 身份认证、角色与 Evidence 原文访问权限

**待定**：认证方式、角色划分，以及谁可以看到 Evidence 原文与未脱敏 payload。

**当前对策**：单用户本地运行；Evidence 原文默认不进入模型上下文与事件流，只保留脱敏摘要、哈希和引用。

**冻结条件**：角色模型确定 + 脱敏策略确定。

> **多租户不在本文范围**：已决为「业务表带 `tenant_id` 字段作架构预留，MVP 不实现隔离逻辑」，见 `productinfo.md` §5.3 与 `docs/spec/data-model.md` §1。
