## 2. 不确定性规则

- 查不到显示“未查到”，不显示 0、空白或“已停产”。
- 未核验身份、过期证据、样例、缓存和 Replay 必须持续可见，导出时仍保留。
- partial 结果不得出现“完整”“全市场最优”或“可执行”。
- 未知数量、价格、库存或交期显示“未知”，不能用破折号造成歧义。
- 多币种或不同包装在未核验换算前不得排成可直接比较的总价。
- 无证据的风险显示“无法判断”和需要补充的信息。
- **多源分歧必须并排呈现各来源的值与采集时间，不得合并为单一数值**；需要单值时由用户选择并记录选择者。
- **采集失败与“该来源无此料”必须分别显示**，不得都呈现为空。
- 文档型结论必须可点回原文位置，并显示文档修订标识与页码。
- 告警的首次发现时间与最近确认时间必须同时可见，不得互相替代。

## 3. Run 与人工节点

界面通过事件流更新进度，但最终状态以 GET Run 为准。连接中断只表示实时显示中断，不表示 Run 失败。

进入 needs_input 时，就地展示具体问题、已有证据和允许选择；提交后恢复同一 Run。进入 awaiting_approval 时必须展示方案版本、content_hash、逐行差异、证据覆盖、风险和未决项。界面不得提供跳过审批或自动批准入口。

用户提交评审时回传自己实际看到的版本和 content_hash；服务端检测到变化则拒绝并要求重新查看。

## 4. Evidence 呈现

每个实质性结论旁提供证据入口。证据卡至少展示来源名称、URL 或记录标识、取得时间、provenance、新鲜度、查询范围和内容摘要。来源不可访问或已失效时明确显示，不移除历史引用。

供应商返回的指令式文本按原始数据展示并转义，不能触发 UI 动作。

## 5. 建议视图

每行至少显示：元件身份、缺口、建议数量、候选来源、MOQ/包装、价格与币种、交期、风险、证据状态和未决问题。金额旁说明已知包含项；税运费未知时不得称“到岸总价”。

无候选或证据不足的行仍保留在方案中，整单标为未就绪。建议不表示库存预留、供应承诺或采购完成。
