## 职责

综合证据下判定：告急、停产、替代可行性、证据是否充分。**被四项能力复用，是系统内核。**

形态：**agent**。划分依据见 `DECISIONS.md` D02。

拥有：生命周期阶段判定、多源分歧裁决、文档修订冲突裁决、证据充分性判定

## 修改前

阅读本目录 `ARCHITECTURE.md`、仓库根 `ARCHITECTURE.md` 的「总体架构图」与「确定性快路径与 Agent 兜底」、`DECISIONS.md` D02、`docs/product/requirements.md` 的 FR-04、FR-11、FR-12；BR-15～17。

## 不变量与 contract

- 判定必须引用 Evidence；无证据时输出「无法确认」，**不得补写常识性结论**。
- 阈值来自 `business_rule` 版本化配置，不写进 prompt 或节点；判定必须记录所用 `policy_version`。
- 分销商字段不得替代制造商官方资料作为生命周期依据。
- Run 内锁定先到的文档修订；观察到更新版本时记录并留待下次，不在本轮混用两个修订。
- 判不出来必须升级人工，**不得放宽条件凑出结论**。
- Worker 之间只传类型化结果，不以自然语言段落互相协商（BR-20）。

## 本模块兜的例外

确定性路径抛出以下 typed 例外时唤起本模块：

- 证据不足以判定
- 多源分歧无法裁决
- 取证中途文档换修订

兜不住必须升级人工，不得自行放宽（BR-18）。
