# 采购业务核模块

> **文档契约** · 类型：模块层 · 读取：进入本模块前读，全文（篇幅短）
> 更新：本模块职责或代码落点变更时由 Codex 写入
> 独占：本模块在根 `ARCHITECTURE.md` 模块表中那一行的展开说明
> 不收录：不变量正文（见同目录 `AGENTS.md`）、跨模块依赖方向（见根 `ARCHITECTURE.md`）

服务入口按执行顺序为 `demand.prepare_demand` → `shortage.calculate_shortages` → `plans.generate_plan`。调用方注入 `Persistence.ProcurementRepository` 并拥有外层事务；本模块不导入数据库产品或调用供应商。API、Worker、审批与 Run 状态迁移不在该切片中。

- `numbers.py`：校验 Decimal 的 NUMERIC(18,6) 边界，拒绝非有限值、float、溢出和隐式舍入。
- `demand.py`：使用项目标识定位当前 BOM，保留调用方提供的产品版本；数量口径未核验时返回 NULL，源行仍在未解决项中。候选确认请求保留厂商、MPN 后缀及身份状态。重复需求 ID 内容改变时拒绝覆盖。
- `shortage.py`：按元件汇总已解决行，生成逐项库存/占用/在途证据与建议限制。本需求已有的实物占用包含在实物中，只算一次；按期且确认的本需求专属在途先抵未满足量，不再加入未分配在途。缺库存快照不宣称数据齐备。结果只追加快照，不分配库存。
- `offers.py`：供应商无关的 `Offer` / `PriceBreak` 是本切片内部输入类型；真实 ToolResult 适配由后续 Tools 实现。显式给定 MOQ/倍数，先算建议数量，再取该数量所在的价格阶梯；保留地区、包装、币种、时间和证据。
- `plans.py`：消费显式选择的报价及持久化缺口快照；每个已解决元件恰需一张同 Run 快照。正缺口缺 MOQ/倍数报价时拒绝生成，不猜采购数量；全部未解决时先请求补全。混合未解决项及缺字段报价可形成部分方案，`ready_for_review=false`；这不代表审批或执行许可。

内容哈希的版本为 1，使用排序键 JSON、规范化 Decimal/UTC 时间和 SHA-256。覆盖需求、未解决项、采购数量/单价、供应商商品、地区/包装/币种、MOQ/倍数/阶梯、库存/交期、报价证据与时间、完整缺口快照及其 ID。相同输入只新增方案版本，哈希保持一致；证据快照更新也保守地产生新哈希。方案 UUID、方案版本与方案创建时间不参与内容哈希。冻结输入保存在 `plan_line.evidence_ref`，可从持久化方案重建哈希；不会自动汇总跨币种或声称到岸总价。
