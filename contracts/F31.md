# F31 Contract：多租户身份、组织隔离、RBAC/RLS 与服务端 API

> 状态：等待用户验收（2026-10-12）｜类型：深度｜里程碑：M1｜spec：§1.1、§2.1

## 目标

建立产品的身份与租户边界：Python API 验证 Supabase access token，PostgreSQL RLS 隔离组织数据；Next 只保留页面、浏览器会话和同源 BFF。

## 当前实现

| 部分 | 文件 | 已验证行为 |
|---|---|---|
| 薄前端与 BFF | `frontend/src/app/`、`frontend/src/lib/bff/`、`frontend/src/lib/supabase/` | 不含 SQL、service role、领域规则、Worker 或 Gateway；API route 只转发 Python。 |
| 组织/RLS 基础 | `supabase/migrations/0001_f31_tenant.sql`、`supabase/tests/f31_rls.sql` | 组织、成员和审计表受 RLS 保护；缺上下文和跨组织读取被拒绝。 |
| Python API | `src/product_api/` | `/health`、`/v1/session`、组织选择、RBAC、统一错误响应；每次身份由 Python 验证。 |
| 真实认证验证 | `tests/test_product_api_supabase_live.py` | 测试用户登录 Supabase 后，Python 重验 token；只可选择自己的临时组织，跨组织返回 403，fixture 自动清理。 |

2026-10-12 已通过 `make api-live-auth-test`。该命令需要用户明确授权和本地测试凭证，不纳入默认测试。

## 边界

- Next 不签发可供 Python 授权的身份断言，不持有 PostgreSQL service role。
- 客户端、cookie 和 BFF 提供的 organization 只是选择提示；Python 必须以已验证 actor 在数据库中重验成员关系。
- `app.set_request_context`、受限 `supplyagent_api` 角色和 RLS 是数据库侧隔离防线。
- F31 不实现 CRM、供应链、Gateway、Worker、Pi 或渠道业务。
