# F40 Contract：产品 Trace 迁入——组织级 Event Log、Artifact、计量、回放与 SSE 投影

> 状态：实现完成，等待用户验收｜类型：深度｜里程碑：M1｜spec：§3.1、§4

## 目标

由 Python 将 Run、Event、Artifact、计量和回放写为组织范围的 SQL 审计事实；Next 只转发 SSE 或渲染读取结果。

## 保留基础

`supabase/migrations/0004_f40_trace.sql` 与 `supabase/tests/f40_trace.sql` 保留为只追加 Event、版本化 Artifact、每 Run 哈希链和组织 RLS 的基础。

## 已实现

- Python `TraceRepository` 在 F31 组织事务内读写 Run、Artifact、Event 和 checkpoint；F35/F42 从 SQL checkpoint 与当前 RLS 事实重建，不把进程或 Pi session 当恢复事实。
- Event-ID SSE 读取投影：先在当前组织 RLS 视野确认 Run，再将 `Last-Event-ID`（优先于 query）映射为同一 Run 的序号；外组织、外 Run 或不存在的游标统一拒绝。响应只输出脱敏 Event，并按不可变 `sequence_no` 回放；连接结束后不订阅实时事件。
- F34 计量与 F35/F42 Pi 事件已映射到 F40 Trace。完整数据集回放、故障注入、分叉和 Eval 属于 F38；实时 Workbench 订阅属于 F33，均未由本 Contract 提前实现。

## SSE 验证（2026-10-21）

`tests/test_product_api_trace.py` 通过离线 API 契约验证：Event-ID 回放、`Last-Event-ID` 对 query 的优先级、跨组织拒绝，以及外 Run/游标拒绝。`make trace-integration-test` 在本地 PostgreSQL/RLS 下通过 Trace 读取/隔离与 Artifact 并发版本验证。该 SSE 切片只做有限历史回放，不证明 F33 的实时订阅或 F38 的全量回放能力。

## Trace SQL 加固验证（2026-10-15）

- `0016_f40_trace_hardening.sql` 显式撤销四个 `SECURITY DEFINER` Trace 函数的 PUBLIC execute，并仅授予 `supplyagent_api`；写入 RLS policy 仅允许函数 owner，防止未来误授 API 表写权限绕开命令函数。
- `trace_run_cursor_consistency` trigger 强制 Run 游标与最后一条不可变 Event 对应；禁止更改 Run 身份字段、序号倒退/跳跃和末端哈希改写。`verify_trace_chain()` 现在还验证连续序号与 Run 末端指针。
- Artifact 版本以 `(organization_id, artifact_key)` 的事务级 advisory lock 串行化；Artifact/Event 的 Case 必须与 Run Case 完全一致（含 NULL）。
- Artifact 通过 `TraceRepository.get_artifact` / `list_artifacts` 从受现有 `trace_artifact` SELECT RLS 限制的表读取；不引入绕过 RLS 的读取函数。`content_hash` 由 SQL 唯一计算，固定为 SHA-256(UTF-8(`jsonb_build_object(artifact_type, redacted_summary, redacted_payload)::text`)) 的小写十六进制值；它覆盖这三个语义内容字段，不覆盖 Run、ID、版本等定位字段。Python 不再传入或声明该 hash。
- 该指纹可用于读回 Artifact 后的数据库内容验真；当前 Artifact 尚未定义对象存储 key/version/etag，故不声明已具备对象存储一致性校验。
- 已通过：`make trace-test`、`make trace-integration-test`（真实 PostgreSQL 的跨 Case 拒绝及并发同 key 版本为 1/2）、`make f42-integration-test` 与 `make check`（197 passed，20 deselected，2 条既有 Starlette 弃用警告）。

## 边界

- 浏览器、Pi 和 Redis 不是 Trace 权威写入者。
- Trace 不保存密钥、原始 BYOK 或未脱敏客户正文。
- 回放不得触发真实 Provider、渠道或供应商。
- 单个 Run 的 Event 链有意串行化：优先保证可审计的总顺序；若未来实测出现高频并发，使用子 Run/子链及汇总 terminal hash，而不是削弱本链的一致性。
