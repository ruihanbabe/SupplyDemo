# F39 Contract：供应链领域迁入——组织范围服务与模拟环境分层

> 状态：实现完成，等待用户验收｜类型：深度｜里程碑：M1｜spec：§3、§3.1

## 目标

由 Python 提供组织范围的供应链事实、确定性影响计算和 API；`simenv` 只保留为测试/Eval 后端，不能成为产品 API 或模型工具。

## 保留基础

`supabase/migrations/0002_f39_supply.sql`、`0003_f39_supply_timeline.sql` 与对应 SQL 测试保留为组织 RLS 的供应链事实基础：案子、库存位置、需求和到货记录。数量或日期未知时必须保持 NULL，不得猜测为零。

## 实现范围与验收

- Python `SupplyRepository` 在 F31 已验证的同一组织事务中读取供应链事实，不能自行连接或绕过 RLS。
- Demo 第一版由 `supplyagent_api` 在 F31 事务内直接写入人工供应事实；RLS 只允许当前组织的已验证成员写入。F44 进一步要求 Python API 在同一事务中确认成员角色含 `supply:propose`，才允许录入 Case、库存、需求或到货。浏览器没有数据库凭证；细粒度 scope/对象关系授权仍延后设计。
- FastAPI 提供 Case、事实录入/读取与 `GET /v1/supply/impact`；每个业务请求都必须提供组织选择提示，Python 以 token actor 和 RLS 重新核验。
- Case 的 `scope` 仅为业务上下文：料号、库位、来源引用和标签的有限扁平集合；它不是成员权限 scope，不能承载自由文本、嵌套外部对象或 Agent 指令。
- 影响计算是 Python 的确定性纯函数：按日期投影可用量，计算首次缺料日；NULL 数量或日期继续以 NULL/unknown 返回，绝不补零或猜测。
- 离线 HTTP/计算测试与本地 PostgreSQL RLS/命令/端到端测试均须通过；不接任何真实 ERP、供应商或采购执行器。
