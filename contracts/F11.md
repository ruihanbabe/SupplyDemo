# F11 Contract：权限 L1/L2

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度 ｜ 里程碑：M2 ｜ spec：§5.5、§3.4、§2.1、G1、G8 ｜ 依赖：F07

## 目标
把 F07 代理层里"执行者 → 工具名集合"的最简白名单换成 spec §5.5 的 L1 可见性 + L2 调用时检查：工具按 R0/R1/R2 分级，每次调用凭代码签发的能力令牌校验工具与作用域，子任务令牌只能收窄；每个动作记代表链。另补两层底座（数据库角色、出站白名单）与凭证隔离脱敏。L3 动作门控归 F12。

## 做什么（`src/permissions/`，配置 `config/permissions.yaml`）
1. **风险分级**：`ToolDef` 增加 `risk`（R0/R1/R2，默认 R0）与 `scoped`（是否受料号作用域约束）。环境、分销商、留档、`dispatch_task` / `ask_user` / `end_segment` 为 R0；`propose_goal_revision`、`report_to_planner`、`create_po_draft`、`request_approval` 为 R1；`submit_po` 为 R2。
2. **能力令牌**（`tokens.py`）：`Authority` 签发，HMAC 签名（进程内密钥），代理层每次调用验签；令牌对象由 Runtime 持有、只以 ID 出现在事件里，不进模型上下文。
   - 字段：令牌号、执行者、案子、工具集合、作用域（料号集合，空 = 不限）、模式（S1 / S3）、父令牌、代表链。
   - 根令牌：活跃段开始时签给编排者；工具 = 配置里编排者与其全部可派执行者的工具之并（本案能力上限）；模式取开案内容 `mode`，缺省按配置 `default_mode`（默认 S3 只读，最小权限；路由归 F22）。
   - **衰减**：派任务时签子令牌，工具 = 父工具 ∩ 该执行者配置工具（∩ 执行者注册的工具）；作用域 = `dispatch_task` 新增可选参数 `scope`（料号），须是父作用域子集；越界直接拒绝派发。R1/R2 工具不会出现在子令牌里（配置 `write_executors` 只有编排者）。
3. **L1 可见性**：执行者看到的工具 = 令牌工具 ∩ 该执行者配置工具 ∩ 当前模式允许的风险级（配置：S1 → R0/R1/R2，S3 → R0）。循环传给模型的工具表按此过滤。
4. **L2 调用时检查**（代理层管道第①步）：验签 → 工具存在 → 在可见集合内 → R1/R2 仅 `write_executors` → `scoped` 工具的料号参数 ⊆ 作用域 → 留档记录属于本案。拒绝返回 `forbidden`（不可重试）+ 原因 + 合法路径引导（配置 `guidance`，如"改排产 / 改工单 → report_to_planner"）；编造的工具名仍按"不存在"并列出可见工具（A6）。
5. **代表链**：每条 `tool_call`、`task_dispatched` 事件的 `meta` 记 `{token, executor, on_behalf_of, case_id, initiated_by, risk}`（子 Agent → 替哪个编排者 → 哪个案子 → 由哪个事件或人发起）。
6. **反复越权**：执行者循环内被拒（forbidden / 工具不存在）累计达配置次数即以 unfinished 结束，原因写明（计入 §5.3 循环检测，受 `loop_detection` 开关）。
7. **凭证隔离与脱敏**（`secrets.py`）：`Credentials` 只从环境变量读取、只交给对应 Server 的后端，`repr` 不显示值；代理层在留档、事件、错误信息写出前统一脱敏（敏感键名如 authorization / api_key / token / secret / password / cookie，URL 查询参数同名项，以及已登记凭证的原值）。
8. **出站白名单**（`egress.py`）：`check_url`（仅 HTTPS、域名在该组件白名单内、解析出的地址不得是内网 / 回环 / 链路本地 / 保留地址）、`check_redirect`（每一跳都过 `check_url`）、`check_download`（大小上限、只接受 PDF）。配置按组件分：各分销商 Server 只允许自己的上游域名；datasheet 下载为厂商 + 三家分销商域名。本 Feature 只提供检查函数与测试（DNS 解析可注入），真实下载归 F19。
9. **数据库角色**（迁移 `0006_roles`）：`supplyagent_agent_ro` 只读（SELECT 环境、Session、留档、计量、`hw_part`）；`supplyagent_procurement` 另可 INSERT `env_write`（采购写入）。均为 NOLOGIN 角色，应用连接改用登录角色归 F29 部署。
10. **接入改动**：`ToolProxy` 用 `PermissionGuard` 取代 `whitelist`，`call` 改为凭令牌（执行者、身份、案子都从令牌取，不信调用方传参）；F09 活跃段签根令牌、Dispatcher 签子令牌（代码组件也拿令牌，经 `ctx["token"]` 调代理层）；控制工具处理函数经 `CallContext.token` 拿到调用者令牌。
11. **消融开关**：`capability_scope`——false 时不做作用域检查与作用域衰减（工具集合与风险级检查照常，它们是 G1/G8 底线）。

## 不做什么
- L3 证据门控、审批令牌（F12）；污点追踪与汇点检查（F13）；Web 登录与人的角色（F25）；路由决定模式（F22）。
- 真实 datasheet 下载与分销商真实后端（F19 / 用户授权）；登录角色与连接串切换（F29）。
