## 接线与边界

按用户最新确认，使用 OpenAI 兼容 Chat Completions；复用 Pi 0.73.1 的 openai-completions Adapter，接入智谱官方 `/api/paas/v4/chat/completions`；不把 Chat 强行转成 Responses。固定 provider=zhipu、model=glm-4.7-flash；免费路径拒绝其他模型及非零价格，不自动回退付费型号。Python 持有 Key，Pi 只持 Gateway 短期能力。关闭 thinking，先验证工具与 JSON 业务交接；不将 reasoning_content 当最终回答或业务证据。

Gateway /v1/model 返回协议与兼容参数；GLM 使用 /v1/chat/completions。双方保留 OpenAI 兼容消息/调用 ID，内部工具名仍经 F49 别名映射。私有 model_exchange 记录 OpenAI 兼容 GLM 请求及最终消息/usage，schema/protocol 标签明确；公开 Trace 不含正文或凭证。计量未知与流中断不能当零 token 成功；零价格仅代表选定免费模型价格，不代表无限配额或请求一定可用。

0028 仅扩充 model_policy.provider 允许 zhipu；不增加新的业务表。业务库仍待用户确认后统一应用。通用模型入口开关 SUPPLYAGENT_MODEL_GATEWAY_ENABLED 默认关闭；F49 旧 Responses 开关只兼容 OpenAI 入口。

## 实现与验收记录

- `glm.py` 的 GlmOpenAICompatibleProvider 为固定官方端点的薄 HTTP 转发：不使用智谱专用 SDK，不自制消息转换；Pi 通过 OpenAI SDK 和 openai-completions Adapter 处理消息及工具。
- `gateway.py` 根据可信模型策略返回协议/compat，分别提供 Responses 与 Chat Completions 路由；协议不匹配拒绝。GLM 私有记录保存有界的 OpenAI 兼容分片、usage 和结束原因，记录 provider 鉴权失败的安全状态元数据。
- `app.py` 增加 zhipu admission；`model_exchange.policy_snapshot.model_api` 明确实际 API；业务 Context 记录模型策略与 scoped-http 传输，不把所有 Gateway 运行误标为 Responses。
- `0028_f50_glm.sql` 只扩充 provider 枚举；调用关联和私有 RLS 复用 F49。
- 既有 SUPPLYAGENT_LLM_ZHIPU_API_KEY 仅由 Python 在 credential_ref=ZHIPU 时读取；也支持 SUPPLYAGENT_MODEL_SECRET_ZHIPU。签名能力与消息协议不携带原始 Key。
