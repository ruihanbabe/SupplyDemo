# F05 Contract：模拟人工（冻结为 Eval 资产）

> 状态：冻结 / `eval_only`（2026-10-09 用户决定不再作为产品 Feature 推进）｜类型：最小｜原里程碑：M1｜历史 spec：§4.5、§3.4 人工节点表、§6 知识库 B 写入、G8｜依赖：F03（另接 F12、F20、F22 的现有人工入口）

## 冻结决定

本 Contract 所列代码保留在工作树中，供固定样例、回归测试和后续 Eval 使用；它**不是** v0.4 的真人审批、CRM 工作台、Pi Agent 工具或渠道能力。不得继续为它增加产品入口、Web 页面或模型可调用接口。

若将来需要复用，F39 负责把 `simenv` 与这些规则隔离为测试/Eval 后端；真实审批与外部副作用由 F37、F41 实现。当前未补跑本 Contract 的集成验收，故不得把下列目标宣称为已验收产品能力。

## 目标
Eval 与演示无人值守时，H1–H5 由配置化规则按模拟日应答（spec §4.5）：主管 1–2 个模拟日后批准，工程师按 mock 替代规则确认，采购员按 mock 别名表确认，计划员回复一个推迟天数。模拟人工只调用现有人工入口（与 F25 Web 同一入口），不走任何捷径；应答写成普通的人工事件，路由照常唤醒案子。

## 做什么
1. **应答规则配置** `config/humans.yaml`（G7）：
   - H2 主管：延迟 1–2 天（按种子 + 请求事件号确定性选取），默认批准；可配驳回条件（金额上限，默认不设）。
   - H1 工程师：mock 替代规则表（原料 → 替代料 → 批准 / 否决），表外默认否决；延迟 1 天。同一张表同时用于 B 级替代确认（`HumanDesk.confirm_substitute`）与替代关系记忆（`KnowledgeBase.confirm`，H1）。
   - H3 采购员：mock 别名表（说法 → 料号），命中才确认（别名记忆）或作答（Resolver 消歧，所答料号须在候选里）；未命中不应答（spec §3.4"不确认，相关任务就不继续"）；延迟 1 天。
   - H4 采购员：目标修订默认确认（可配驳回 / 不应答）；延迟 1 天。
   - H5 计划员：对上报所附 ImpactReport 里预计停线的、尚未开工的工单，各推迟"预计停线天数"（上限可配，默认 5 天）；延迟 1 天。
2. **两个新人工入口**（`src/humans/desks.py`，F25 Web 也用它们）：
   - `PlannerDesk.reply(request_seq, postpone={工单: 天数})`：写 H5 人工决定，再经环境新写入 `postpone_work_order` 推迟工单开工日。
   - `BuyerDesk.resolve(request_seq, mpn)`：H3 料号消歧作答，所答料号须在该请求的候选里，否则抛错；写 H3 人工决定（带料号）。
3. **环境新写入** `postpone_work_order`（F03 预留的"计划员改计划"写入种类）：只接受计划中或缺料停线未开工的工单、天数在配置上限内，带幂等键；先落 `env_write` 再生效，崩溃恢复与回放照常重放。**Agent 没有任何调用它的工具**（G8 不变），只有 `PlannerDesk` 调用。
4. **模拟人工** `SimulatedHumans.respond(day)`（`src/humans/sim.py`）：扫描未处理的 `human_request`，到期的按规则调用上面的入口；已有人工决定或已跳过的不再处理（幂等，所以回放 / 恢复后结果一致）。入口核对不过（如草稿已失效）写 `sim_human_skipped`（原因），不重试。
5. **接入**：`Scheduler.run_day` 在环境推进后、路由前调用挂点，当天的应答当天唤醒案子；`build_runtime(humans=...)` 传规则即启用，默认不启用（Web / 真人时不自动应答）。
6. **补齐请求信号**（改动已有 Feature 的最小一处）：
   - F12 门控因"B 级缺 H1 确认"拒绝时，对该报告首次发 `human_request`（工程师 H1）；此前没有任何请求，工程师无从得知。
   - F22 上报计划员的 `human_request` 补 `node: "H5"`，与其他节点一致。

## 不做什么
- 驳回理由的解析与学习、工程师拒绝理由的学习（spec §4.5 本期不做）；真实发生的驳回按普通失败交回编排者（已有行为）。
- `ask_user`、升级、软声明冲突等通知类请求不在 H1–H5 内，模拟人工不应答。
- H3 消歧作答后把别名落库（spec §6"确认消歧即落库"）推迟到 F25 与 Web 一并做；本期只写人工决定。
- Web 页面（F25）；情景里的人工参数（F04 情景 YAML 引用本配置即可）。

## 验收证据
| 命令 | 通过条件 |
|---|---|
| `make check` | 离线测试：送审后主管在 1–2 天内批准、同种子两次延迟相同，令牌签发后案子被唤醒并提交；表内 B 级替代被确认、表外被否决；别名表命中才确认 / 作答，消歧答候选外料号被拒；目标修订按配置确认；计划员推迟后工单开工日后移、停线天数下降，Agent 工具集中没有推迟工具；草稿失效时写跳过事件不重试；重复调用 `respond` 不重复应答；不传 `humans` 时无任何自动应答 |
| `make test-integration` | Postgres 环境：推迟写入落 `env_write`，崩溃恢复后状态哈希与未崩溃一致（无新迁移） |
