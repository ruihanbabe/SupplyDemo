# F52 Contract：会话、Working State 与每次请求的 Context 管理

状态：2026-10-27 用户审阅后授权按方案开发；awaiting_acceptance，C1–C3 已实现并通过本地/克隆验证；F48 后续顺序实施。默认配置继续使用 F51 v2，v3 不静默降级。

## 目标与权威入口

支持长工具链和跨轮任务：消息完整、任务状态可恢复，每次模型请求有界且可追溯；长期记忆关闭时仍能运行。Compaction 缩减模型输入，不改变原始事实或自动形成长期记忆。

架构见 [spec §2.3/§2.6](../spec.md#23-product-harness-拥有业务控制pi-只执行-agent-turn)；业务规则见 [BL13](../business-logic.md#bl13-短期状态context-装配与压缩f52-目标)；数据见 [DC18/DC21](../data-contract.md#dc18-会话消息工作状态与提交水位f52-目标)；实现见 [Context 模块](../src/product_api/CONTEXT_RUNTIME.md)，传输见 [Pi Context 协议](../pi_sidecar/CONTEXT_PROTOCOL.md)。

## 范围与准入

范围：Conversation/消息提交、原用户与对象关联、Working State/checkpoint、完整工具配对、近期缓冲、每请求装配/预算/引用/取舍快照、渐进读、确定性缩减/摘要、模型切换重算、私有受限分块协议、MemoryPort。F52 不实现 Mem0 后端和长期抽取，空 MemoryPort 必须给出“未使用记忆”并可独立验收。

依赖 F51 的统一调用身份、持久引用与批次协议，以及现有 F35/F40/F42/F45/F49/F50。F51 完整验收后顺序实施 F52，再实施 F48；F52 引入 v3 保留 v2 工具语义，可注入串行 Scheduler，不要求启用并发。F48 消费 F52 的来源提交和装配 Interface，F52 不反向依赖 F48。

必要性：当前 task/instructions/factReferences 和角色启动快照不能提供完整消息/预算/恢复语义。最小路径是持久消息与确定性预算，随后摘要、长期记忆挂接；替代方案“只扩大窗口/只加摘要 prompt”不能保留配对、权限与任务状态。成本是四项存储责任、Python Compiler/Store、Pi 版本化桥接；复用 Job/Trace/Gateway/Pi，不新增编排服务或 Shell/文件能力。

范围之外：新的聊天产品 UI、自由多 Agent 私聊、通用计划修订、局部业务步骤重执行策略、自动模型路由、任意文件读取、完整 Provider 即时撤销、业务审批与渠道。Conversation 的多轮 command Interface 必须可调用验证，不以没有 UI 为由省略会话模型；接入既有问答默认新建单次会话，只有显式授权续接才共享历史。

## 验收矩阵

- 六类对象不混同：Transcript、Buffer、Working State、长期 Memory、ContextSnapshot、CompactionCheckpoint；Conversation/Mission/Run/Job/Invocation/ModelCall 身份分别保留。
- 配对：一条 assistant 多工具调用与全部终态结果不可被拆断；活动批次不压缩；错误不伪造成功；取消/失租不重放半段 Pi session。
- 预算：可信模型实际窗口、output/reasoning、工具 Schema、协议开销与安全余量均计入；强制保留项本身超限时拆分/失败，不删除权限或关键问题。
- 真实性：每 modelCallKey 对应 snapshot、版本/epoch/政策和最终模型消息；来源 body 变换与 Provider 序列化记录各自关联，不能把启动快照当全部模型输入。
- 安全：不同对象/角色/用户不共享私人历史，工具正文不升为指令；派生摘要按依赖权限收窄；撤权、删除和模型 profile 改变后旧 ready 不发送。已发出请求不能宣称撤回。
- 终止：prepare/分块等待响应取消/截止；LLM 摘要失败仍保留原始记录；没有合法投影时报 context_overflow；关闭/任务结束 commit 不等待长期索引。
- 兼容：当前单次业务入口、F36 Artifact、F45 Observation、GLM/Responses 复合调用 ID、F40 脱敏、F51 Scheduler 所有权保持。

## C3 本地实现（2026-10-27）

context_compaction.py 增加闭合前缀摘要与 ContextReader：保留首部任务、最新完整单元和 Working State，达到预算阈值后按原文段落去重，工具正文以持久引用及原有 unknowns/conflicts/时间条件替代；不改写结论。覆盖范围、原始单元 hash、策略、来源引用随 snapshot 保存，0034 将 compaction coverage/sourceManifest/epoch 存入 context_working_state 的独立 compaction 列，保留合法 WorkingState payload，不覆盖 Transcript，也不推进 F48 消费游标。

读取绑定已授权 Conversation，L0 返回目录/尺寸，L1 读取当前有效摘要，L2 按完整消息单元或证据字段分页；读时重新检查私有权限、来源引用/hash 和当前领域权限，每次返回 bytes/估算/剩余 allowance，不能用 ID 或旧缓存绕过。过大单元/单字段明确 context_read_fragment_too_large，可由调用方在总预算内选择更大有界 page；不拆半个工具单元。source_epoch 改变则旧摘要整块失效；原始 message 的更新/删除也推进 epoch，禁止遗忘后继续使用派生快照。

摘要器失败或输出不满足原文约束时不接受该摘要；原消息仍可容纳时继续，否则 context_overflow。没有校准语义评估器和外部摘要模型配置时，默认仅采用逐字、完整段落、可验证去重；不把任意模型摘要当事实。不可重复且过长的受保护文本无法压缩时仍失败，不截断头部目标。此实现没有外部 LLM 摘要费用，也不宣称高压缩率或业务回答质量提升。

验证：f52-check 28 passed；f52-integration-test 13 passed；make check 190 passed、34 deselected、2 条既有警告。覆盖否定/时点/条件/理由/未知保持，摘要失败/伪造/仍超限，来源覆盖、原文读取/配额、私有隔离和来源 epoch 失效，既有两种真实 Pi 原生协议回归。0034 仅克隆验证，业务库未迁移；F52 本地实施完成后等待用户验收，随后按已获授权推进 F48 M1。
