# F32 Contract：CRM 业务域、会话、Kanban 与受控提案

> 状态：完整 CRM 仍延后；F36 P3 获准实现只读事实接线｜类型：深度｜里程碑：M1｜spec：§1.2、§2.7

## 目标

由 Python 提供组织隔离的客户、联系人、商机、会话、任务和不可执行 Proposal；Next 只转发和展示。

## F36 P3 的受限接线

用户于 2026-10-20 确认：F36 可实现一条**只读**的 CRM 事实接线，用于
`opportunity_next_action` Mission。它不是 F32 完成，也不提前实现完整 CRM。

- 读取对象仅限客户、联系人、商机、会话和任务；读取必须仍在 F31 的组织事务、RLS
  与对象 scope 内执行。
- 输入为服务端已验证的 opportunity ID；Repository 返回版本化事实及最小引用定位，
  不能接受模型提供的组织、客户或 SQL 条件。
- 第一份演示数据可以是明确标记 `synthetic` 的企业/客户/商机/会话；导入和写入能力
  不成为此次产品 API，测试 fixture 不得冒充真实客户记录。
- 该接线由 F36 及 F45 的客户事实 Specialist 读取。它不创建 CRM 事实，不改变 Kanban，
  不产生 `crm_proposal`，不发送渠道消息。

完整的人工录入、命令、Kanban、Proposal HTTP API 和 F41 执行继续属于后续 F32/F41
工作，不能因本段读取接线被称为已经完成。

实现状态（2026-10-20）：已实现 `PostgresCrmFactRepository`，只读返回一个商机的
客户、联系人展示名、会话摘要和任务，以及每项的版本化最小引用。Repository 不返回
联系人邮箱，也没有写命令；F45 的商机选择/问答是专用入口，不是通用 CRM CRUD。`make crm-facts-integration-test` 在真实
PostgreSQL/RLS 中证明：同组织可读取、跨组织在 F31 租户入口拒绝、同组织但不在
`scope.member_ids` 的对象不可读。

## 边界

- 模型只能创建不可执行 Proposal，不能直接写 CRM 事实。
- Proposal 批准后的执行属于 F41；渠道发送属于 F37。
- 不把供应链、库存、采购或排产逻辑带入 CRM 服务。

## 验收证据

Python 离线测试与真实 PostgreSQL 测试必须证明：跨组织/跨 scope 拒绝、目标版本冲突显式处理、Proposal 不自动执行、审计不记录正文。

F36 P3 的附加证据是：同一组织、同一 scope 的 opportunity 能返回可引用的客户事实；
跨组织、无成员关系、无对象 scope 或缺失 opportunity 均被拒绝；返回内容只含该
Mission 所需事实，不含其他客户或组织的数据。
