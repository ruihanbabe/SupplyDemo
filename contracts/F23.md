# F23 Contract：子 Agent 与 LLM 函数

> 状态：已写，按用户 2026-09-30 指示"继续做"（固定样例 + 脚本模型，真实调用待授权）直接实现、事后统一验收 ｜ 类型：深度 ｜ 里程碑：M2 ｜ spec：§3.1、§3.2、§3.5、§2.3、§2.4 引用校验 ｜ 依赖：F19、F20、F22

## 目标
把 spec §3.2 的五个 LLM 执行者接进 F22 的节点库：每个只回答一个问题、只产出一种 Artifact；隔离、等级、引用校验都由代码保证，prompt 只是说明（§3.1 原则 4）。

## 做什么（`src/agents/`）
1. **派发器扩展**（F09）：执行者注册项增加三个代码挂点——`brief`（按执行者定制输入格式，隔离由结构保证）、`scope`（代码强制子令牌的料号作用域）、`post`（LLM 输出交回前由代码后处理：引用校验、等级汇总、打标）。
2. **原料画像** `part_profile`（子 Agent）→ `PartProfile`：工具只有 datasheet / 板级文档四件套；必定加载 PartAnalyst Skill、注入术语与该品类比对清单；作用域 = 原料 + 板级文档。每条约束附引用，代码逐条引用校验，不通过的约束标"无法确认"；通过的字段 F13 去污为已校验，依赖所引 datasheet 版本。
3. **替代检索** `substitute_search`（子 Agent，每个来源一份）→ `CandidateSet`：本期来源只有知识库 B（`kb_substitutes`，含原理图未验证种子）；DigiKey 参数检索来源待授权（注册表里不出现，编排者派不了）。输出模型不含等级字段（多写即校验不过），**不评等级**。
4. **Verifier**（子 Agent，每个候选一份）→ `VerificationReport`：输入格式只有 PartProfile 的约束、**单个**候选料号与该品类比对清单——**没有价格、没有检索过程**（由 `brief` 结构保证，即使输入里带了 CandidateSet / SourcingQuote 也不会进上下文）；作用域 = 原料 + 该候选（读第三颗料的 datasheet 被 F11 拒绝）；必定加载替代料评估 Skill。逐项结论附引用，代码引用校验，不通过的项降级为"证据不足"；**等级由代码按比对清单汇总**（F21 grade，等级字段标可信，F12 门控据此判定）；清单外的项忽略、缺的项按证据不足。
5. **Resolver**（代码 + LLM 函数，三层）→ `ResolvedPart`：规则层（去空格与大小写、剥常见包装后缀后精确匹配 BOM 目录）→ 检索层（知识库 B 已确认别名、料号前缀 / 相似度候选）→ LLM 消歧（只能从候选里选，给置信度）；选了列表外的料号或置信度低于配置阈值 → 交采购员确认（H3，`human_request`），不擅自定。
6. **Explainer**（LLM 函数）→ `Explanation`：按受众（采购员 / 主管 / 工程师 / 计划员）写说明，必定加载 Explainer Skill；输出里的数字须能在输入 Artifact 中找到，找不到的列入"无法确认"并整段标为不可信（F16 只以引用块展示）。
7. **接入**：`build_runtime` 默认注册以上五个节点（F22 节点集合已含），模型链按执行者名取 `config/models.yaml`；权限配置补各执行者角色工具。
8. **消融开关**：`verifier_isolation`（false 时 Verifier 输入不做结构隔离，把全部输入原样给它，对比"看到价格与检索过程"的影响）、`citation_check`（false 时不做引用校验、不降级）。Skill 强制加载与比对清单注入沿用 F20 的 `glossary_injection`，另加 `skill_injection`。

## 不做什么
- DigiKey 参数检索来源与参数 Server（需真实调用授权）；真实模型调用；S3 问答的结论输出路径（F24）。
