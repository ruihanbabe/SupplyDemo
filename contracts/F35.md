# F35 Contract：SQL Durable Runtime、独立 Worker/cron 与可恢复队列

## 2026-10-28 恢复增强R1（当前实施单元）

用户按顺序授权在F38当前入口/F33只读单元后补恢复机制。范围：透传安全细原因、永久错误与有限重试区分；固定claim/业务完成/失败/终态前的checkpoint hooks，复用SQL Artifact/Event与Job租约，不新建调度器/插件体系或数据库表。默认仍整Job新turn重跑；自动成功分支复用须有依赖重验和独立后续证据，不以事件序号恢复Pi内存。

checkpoint须在有效owner/generation/lease行锁保护的事务中写入，提交失败不报告业务成功；取消/失租不能借hook写入。0042仅增加受限lock_runtime_attempt函数，必要性是API数据库角色无runtime_job直接UPDATE权限，不能靠应用SELECT FOR UPDATE锁表；复用现有表，不扩大表写权限，不改历史迁移。非取消已知永久错误使用现有SQL失败函数的终止次数策略。未知模型失败继续原有限重试，不宣称Provider费用可安全重复。

新Worker签发的ModelCapability绑定job/owner/generation；Gateway在模型描述、预算预留与交换接受前经0042重验，失租/完成/取消后拒绝新请求。流已发出不承诺撤回，费用结算不依赖活动租约以免丢账；显式旧/独立无Job能力保留原短期边界，不能将其称为即时撤销。新增DDL仅克隆应用；实际部署须先确认0042并协调Python/Gateway/Worker版本。

验收：权限/绑定/确定性Context超限不反复重试，临时失败仍有限重试，根因脱敏留证，旧代次checkpoint拒绝，hook失败不报完成；真实克隆与原Worker回归。运行说明与F52负责的消息/Working State语义保持。

## 目标

由 Python Worker 领取和恢复 SQL Job，再通过 F42 `AgentEnginePort` 执行 turn。HTTP 只入队，SQL 是唯一运行事实。

Web 默认常驻 Worker、可选 cron 单次领取的运行契约补充清单见 [Model Gateway 与 Worker 运行契约](../docs/design/model-gateway-worker-contract.md)。报告、退出码、实例标识与最低停止语义已按用户授权实现，新增证据见该文；系统 cron 安装与生产部署仍未验收。

## 保留基础

`supabase/migrations/0010_f35_runtime.sql` 与 `supabase/tests/f35_runtime.sql` 保留为 Mission、Run、Job、claim、lease、heartbeat、retry、cancel 和 reaper 的 SQL 原子语义基础。

## 已实现

- HTTP 在已认证的组织事务中幂等创建供应调查 Mission/Run/Job，仅允许 Case scope 内的料号；取消命令要求 `supply:propose`。
- Python 单组织 Worker：claim、heartbeat、代次隔离、reaper、重试、取消与失败分类；`--once` 可由 cron 调用，常驻模式只轮询本组织 SQL 队列。领取旧格式或无效上下文 Job 时安全标记失败，不会反复卡住队列。
- 领取时从 SQL 的 Case/Run/context 引用和 F40 checkpoint 重建最小输入、验 Trace 链；每次工具调用重新读取当前 RLS 业务事实。每个 Pi 事件独立提交至 F40 Trace，不使用本地 session 作为恢复事实。
- Worker 只依赖 F42 `AgentEnginePort`，具体 Pi 装配留在进程入口。单 Run HTTP Gateway 能力仅由 Python Worker 签发；没有模型策略或 Gateway 配置时，非显式 Replay 模式安全失败。
- 领取、续租、完成、失败和回收只允许本组织 `maintainer` 且成员 scope 含 `runtimeWorker: true` 的身份执行；普通成员不能伪装 Worker。

## 边界

- Next 不运行 Worker、Runtime 或 Agent turn。
- Redis 只用于协调，不是业务事实来源。
- F35 不定义 Pi JSONL 或 turn 内工具循环，这些属于 F42。
- 任何 Agent Engine 都不拥有数据库、Provider、渠道或组织凭证，也不以本地 session 作为恢复事实。

## 已验收的本地证据（2026-10-21）

`make runtime-test` 通过本地 PostgreSQL 的幂等、成员隔离、过期回收、代次 fencing 和取消测试；`make runtime-check` 2 passed；`make runtime-integration-test` 1 passed，在隔离数据库克隆中验证 HTTP 幂等入队 → 专用组织 Worker → 真实 Pi Replay → 当前事实工具 → 持久 Trace/验链 → Job 完成，且旧格式 Job 安全失败。隔离克隆在测试后删除。真实付费 Provider 未调用，当时未演练进程退出/重启；后续本地进程证据见运行说明，生产运维调度仍需单独验收；恢复是从 checkpoint 引用发起新 turn，不承诺恢复 Pi 内存中的逐 token 状态。

F36 完整的本地确定性 Mission 已接入同一 Worker：它并行执行必需的客户事实、商机诊断、业务政策，以及按条件启用的供应链分支；随后独立 review，再由唯一父汇总生成不可执行 `ProposalDraft`。只读工具结果和每个 Specialist/Review/汇总结果都先作为 F40 Artifact/Event 持久化；Citation 必须重新匹配同 Trace/Case 的 Artifact ID、版本和哈希。P3 的长期记忆只允许 candidate、人工确认或确定性来源确认、知识更新后的 pending_revalidation、以及撤销，状态转换均写入 F40 Event。`make runtime-check`（2 passed）、`make runtime-integration-test`（1 passed）、`make f36-check`（37 passed）和 `make f36-integration-test`（1 passed）已在本地确定性 Replay 与 PostgreSQL/RLS 边界通过。

这些证据不代表已接通付费或真实 Provider/BYOK、外部供应商/渠道，也不代表生产部署或系统 cron 运维已验证；恢复仍是从 SQL checkpoint 引用发起新 turn，不承诺恢复 Pi 内存中的逐 token 状态。
