# F35 Contract：SQL Durable Runtime、独立 Worker/cron 与可恢复队列

> 状态：实现完成，等待用户验收｜类型：深度｜里程碑：M2｜spec：§2.2、§3、§4

## 目标

由 Python Worker 领取和恢复 SQL Job，再通过 F42 `AgentEnginePort` 执行 turn。HTTP 只入队，SQL 是唯一运行事实。

## 保留基础

`supabase/migrations/0010_f35_runtime.sql` 与 `supabase/tests/f35_runtime.sql` 保留为 Mission、Run、Job、claim、lease、heartbeat、retry、cancel 和 reaper 的 SQL 原子语义基础。

## 已实现

- HTTP 在已认证的组织事务中幂等创建供应调查 Mission/Run/Job，仅允许 Case scope 内的料号；取消命令要求 `supply:propose`。
- Python 单组织 Worker：claim、heartbeat、代次隔离、reaper、重试、取消与失败分类；`--once` 可由 cron 调用，常驻模式只轮询本组织 SQL 队列。领取旧格式或无效上下文 Job 时安全标记失败，不会反复卡住队列。
- 领取时从 SQL 的 Case/Run/context 引用和 F40 checkpoint 重建最小输入、验 Trace 链；每次工具调用重新读取当前 RLS 业务事实。每个 Pi 事件独立提交至 F40 Trace，不使用本地 session 作为恢复事实。
- Worker 只依赖 F42 `AgentEnginePort`，具体 Pi 装配留在进程入口。单 Run HTTP Gateway 能力仅由 Python Worker 签发；没有模型策略或 Gateway 配置时，非显式 Replay 模式安全失败。
- 领取、续租、完成、失败和回收只允许本组织 `maintainer` 且成员 scope 含 `runtimeWorker: true` 的身份执行；普通成员不能伪装 Worker。

## 边界

- Next 不运行 Worker、Runtime 或 Agent turn。
- Redis 只用于协调，不是业务事实来源。
- F35 不定义 Pi JSONL 或 turn 内工具循环，这些属于 F42。
- 任何 Agent Engine 都不拥有数据库、Provider、渠道或组织凭证，也不以本地 session 作为恢复事实。

## 当前进度（2026-10-20）

`make runtime-test` 通过本地 PostgreSQL 的幂等、成员隔离、过期回收、代次 fencing 和取消测试；`make runtime-check` 2 passed；`make runtime-integration-test` 1 passed，在隔离数据库克隆中验证 HTTP 幂等入队 → 专用组织 Worker → 真实 Pi Replay → 当前事实工具 → 持久 Trace/验链 → Job 完成，且旧格式 Job 安全失败。隔离克隆在测试后删除。真实付费 Provider 未调用，实际部署的进程退出/重启与运维调度尚未演练，需单独部署验收；恢复是从 checkpoint 引用发起新 turn，不承诺恢复 Pi 内存中的逐 token 状态。

F36 P2c 的第一个持久切片已接入同一 Worker：只读工具结果先作为 F40 `tool_result` Artifact 持久化，Pi 返回的 Citation 必须重新匹配同 Trace/Case 的 Artifact ID、版本和哈希；经校验的 `specialist_result` Artifact 写入后才完成 Job。集成测试验证了两个工具 Artifact、一个 Specialist Artifact 和 8 条 Trace Event。这仍只是一个 `supply_risk` Job，不代表多 Specialist Mission 已完成。
