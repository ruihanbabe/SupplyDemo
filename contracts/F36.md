# F36 Contract：有界 Specialist、证据 Claim、企业知识与父 Agent 汇总

> 状态：进行中，Contract 已于 2026-10-20 确认 ｜ 类型：深度 ｜ 里程碑：M3 ｜ spec：§2.5、§2.6、§3

## 产品目标

围绕“客户或商机受到交付、价格、库存或供应链变化影响，需要形成可审阅的下一步建议”建立有界 Agent 协作。F36 按真实业务判断责任划分 Specialist，而不是按现有数据或界面名称划分。

图中的“CRM 情报员、销售运营、客户沟通、CRM 主管”保留为 Workbench Mission 入口；它们不是四套独立运行时。Python Product Harness 根据 Mission 模板编排 Specialist，Pi/其他 Agent Engine 只执行单个 turn。

## 业务角色与边界

### 父 Agent / Mission Orchestrator

父 Agent 创建有界任务图，只接收受权限过滤的 Claim、引用、未知项、冲突和 review 结果。它负责判断 Mission 是否完整、汇总 Recommendation，并独占 `ProposalDraftArtifact` 的生成入口。

父 Agent不直接查询全量数据库，不重做 Specialist 判断，不覆盖未知或冲突，不执行 Proposal。真实 Proposal、Approval、Execution 和外部副作用属于 F41。

### 三个必需 Specialist

| Specialist | 只负责 | 明确不负责 |
|---|---|---|
| 客户事实 | 从 F32 客户、联系人、商机、任务和会话中返回有引用的事实、未知和冲突 | 商机诊断、政策解释、动作建议、CRM 写入 |
| 商机诊断 | 根据已确认 Claim 识别阶段不一致、成交阻碍、承诺风险和下一步选择 | 补造客户事实、批准例外、生成或执行 Proposal |
| 业务政策 | 按版本化政策返回允许、禁止、审批要求、证据要求和政策冲突 | 判断客户说了什么、批准例外、执行业务动作 |

### 条件性 Specialist

- 供应链风险：仅当客户/商机与供应 Case、产品或订单关联时启用；数值由 F39 确定性服务产生，模型只解释其业务影响。
- 采购策略：仅当缓解方案确实需要报价、替代料或重新采购时启用；报价采集和计算是工具/领域服务，Specialist 只判断商业权衡。

### 不是 Specialist 的组件

SQL/BOM 查询、全文或向量检索、报价采集、citation 校验、数值计算和最终文字格式化是工具、领域服务或确定性校验器，不因使用模型就升级为独立 Specialist。

## Mission 模板与并发

第一类产品 Mission 为 `opportunity_next_action`：客户事实、商机诊断和业务政策为必需角色；供应链风险与采购策略由已验证的业务关联条件启用，不能由模型凭空添加。

- 相互独立的只读检索与 review 可以并行。
- 商机诊断依赖客户事实及已启用的领域 Claim，按任务图顺序运行。
- 同一 Mission 只能有一个活动父汇总/ProposalDraft 写入路径，`proposalMaxParallel=1`。
- 并行子任务不共享原始上下文，只交换版本化 Artifact 引用和最小 Claim 摘要。

## Claim、Review 与质量状态

Specialist 必须返回结构化 Claim，而不是自由文本。Claim 至少包含：稳定 ID、主题、类型、结论、生产者、组织/任务 scope、引用、未知项、冲突和质量状态。

Citation 至少固定来源类型、对象 ID、不可变版本/修订、位置和片段哈希。事实性结论没有可验证 citation 时必须为 `unsupported` 或“无法确认”，不得标为 `supported`。

Claim 质量状态固定为：

- `supported`：引用存在、权限允许且校验通过；
- `conflicting`：来源互相冲突；
- `stale`：引用版本已失效；
- `unsupported`：没有足够证据；
- `needs_review`：需要人工判断；
- `rejected`：权限、引用或结构校验失败。

独立 Reviewer 只读取目标 Claim 和其有权重新读取的证据，返回 `approved`、`needs_review` 或 `rejected`。Reviewer 不读取其他 Specialist 私有上下文，也不把模型自报置信度当质量证据。

Mission 整体状态固定为：

- `complete`：所有必需及已启用条件角色均完成，Claim 有效且独立 review 通过；
- `partial`：保留了部分有效结果，但非必需分支未完成；
- `needs_review`：存在冲突、过期、证据不足或人工判断项；
- `blocked`：必需角色、权限或关键证据缺失，或 review 拒绝。

`partial`、`needs_review` 和 `blocked` 可保存、回放和展示，但不得等同完整生产验收，也不得形成可执行 Proposal。

## 企业知识、Wiki 与长期记忆

知识库支持组织私有文件、Wiki 和 datasheet 的导入、内容哈希版本、ACL、全文检索、可选 embedding、页/片段 citation、撤销和失效传播。检索先执行组织/文档 ACL，再排序候选；向量检索不能替代权限过滤和引用校验。

长期记忆只接受人工确认或确定性来源。模型只能提出候选；候选、确认、撤销、过期和待重验均进入 F40 Event Log。文档版本更新或撤销后，引用旧版本的 Claim、Recommendation 和记忆必须降级，不自动改写。

## F01–F29 复用规则

只在资产满足上述业务责任时复用：F06 提供 Event/Artifact 语义；F07/F11 提供受控工具与 scope；F03/F21/F39 提供确定性供应计算；F19/F20 提供文档、引用和确认记忆素材；F22/F23 仅提供任务图、隔离和引用验证的历史参考。旧代码和固定样例不因可复用而决定 Specialist 边界，也不自动获得产品验收状态。

## 分阶段实现与证据

### P0：责任与质量边界

实现 Specialist/Claim/Citation/Review/MissionPlan/ParentRecommendation 的 Python 领域契约，证明必需与条件角色、证据门禁、独立 review、部分结果降级和父 Agent 单写者规则。此阶段不声明真实 Specialist turn、Wiki 或 Proposal 已接通。

### P1：组织知识与 citation

实现组织文档、不可变版本、ACL、全文检索、引用校验、撤销和失效传播；真实 PostgreSQL/RLS 集成必须证明跨组织拒绝。第一版不以 embedding 作为验收前提。

实现状态：已完成核心路径。当前支持 Markdown/TXT/PDF 的本地受限解析，组织公开/指定角色 ACL，官方/模拟来源标记，不可变版本与 Chunk 哈希，PostgreSQL `simple` 全文检索，Citation 校验，新版本自动使旧引用过期，以及版本撤销/整篇撤回。公开资料只保存原创摘要和来源，不复制第三方全文；embedding、OCR、Word/Excel 与网页自动抓取不在 P1。

### P2：Specialist 运行与父子汇总

通过 F42 `AgentEnginePort` 执行三类必需 Specialist 和条件分支；通过 F35 Mission/Run/Job 恢复，所有 Claim、review 和父汇总写入 F40。只读分支并行，父汇总和 ProposalDraft 串行。

实现拆成三个可独立验证的子单元：

1. P2a 端口与结果门禁：`SpecialistAssignment` 只能启用精确的 R0 工具集，`AgentEnginePort` 只能返回有大小限制的结构化 output；服务端重建组织、Mission、角色和 ID，并校验 Citation。
2. P2b 真实 Pi 结构化返回：扩展 SupplyAgent 自有 JSONL 协议和 Replay，使锁定版本的 Pi sidecar 能返回同一份受限 output，而不将原始模型正文当作业务结果。
3. P2c Durable Mission：由 F35 运行多个 Specialist，将 Claim、review、失败和部分结果写入 F40，最后串行运行父汇总。

### P3：领域接线与记忆

接入 F32 CRM 读取和 F39 供应链事实；实现长期记忆候选、人工确认、撤销与待重验。F41 验收前只产生不可执行的 `ProposalDraftArtifact`。

F32 在本阶段只开放 `opportunity_next_action` 所需的受 RLS/scope 保护的只读事实
Repository，具体边界见 `contracts/F32.md` 的“F36 P3 的受限接线”。它不表示完整
F32 CRM 已恢复开发。首个演示业务使用 HackRF One 的固定 GitHub 图纸及其派生零件表；
首批关键料为 Skyworks `SKY13453-385LF`。演示企业、客户、商机、会话、报价和内部
政策均必须标记 `synthetic`；厂商资料和分销商信息必须保留来源链接、采集时间、版本或
有效期，不得作为价格/库存/交期的永久事实。

分销商 API 仅在用户已配置凭证并明确选定的单一料号、单次研究/复核中调用；不批量抓取，
不把凭证、完整响应或不可复核的瞬时库存写入知识文档。报价采集与数值比较仍是确定性工具，
不是 Specialist。

| 业务验收 | 一个机会下一步 Mission 展示事实、诊断、政策及条件性供应风险；只有完整且 review 通过的结果形成 ProposalDraft。 |

## 不做什么

- F36 不实现 F41 的 Proposal/Approval/Execution，不调用渠道或真实采购执行器。
- 不把 Workbench 的四个入口实现为四套拥有重复工具和上下文的后台 Agent。
- 不把数据库查询、搜索、校验或格式化包装成无独立判断价值的 Agent。
- 不将原始工具输出、其他 Specialist 私有上下文、凭证或污点元数据交给父 Agent。
- 不为提高旧资产复用率而编造不影响真实业务决策的场景。
