# F36 Contract：Specialist、企业知识/Wiki/RAG、引用与长期记忆

> 状态：草案，待用户确认 ｜ 类型：深度 ｜ 里程碑：M3 ｜ spec：§2.4、§2.5、§3

## 目标

在 F35 已提供的 PiRuntimeAdapter/Agent loop 之上，实现图中的三类 Specialist 和知识底座，并把现有采购 Verifier/datasheet 能力纳入统一的组织级证据与记忆模型。

## 2026-10-10 架构约束

Specialist 策略、知识访问、citation 校验、记忆确认和 Artifact 装配由 Python Harness 模块实现；Next 只展示其受权限过滤后的结果。若 Pi 上游能力需要 Node，仅允许通过 F35 定义的无状态 JSONL sidecar 适配，不得把 Specialist 或知识权限逻辑放入 Node。

## 做什么

1. 为主 Agent 和 Specialist 定义明确输入/输出 Artifact、工具白名单、组织 scope、上下文上限和父子汇总协议。
2. 至少提供客户事实/商机、供应链影响、采购/报价、知识检索、Verifier、Explainer Specialist；独立 review 可并行，写提案串行。
3. 知识库支持组织私有文件/Wiki/datasheet：上传/导入、内容哈希版本、ACL、全文检索、可选 embedding、引用页/片段、撤销和失效传播。
4. 事实性结论必须带业务记录或知识版本 citation；缺证据输出“无法确认”，不由模型补全。
5. 长期记忆只接受人工确认或确定性来源；模型提议、确认、撤销、待重验均进 Event Log 和审计。

## 不做什么

- 不让 vector 检索替代权限过滤和引用校验。
- 不将原始工具输出、其他 Specialist 隐私上下文或污点元数据直接交给主 Agent。
