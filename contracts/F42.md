# F42 Contract：Python Product Harness 与可替换的 Pi Agent Engine

> 状态：实现完成，等待用户验收｜类型：深度｜里程碑：M2｜spec：§2.2、§2.3、§2.5、§3.1

## 产品目标

建立 Python 拥有的 Product Harness，并把锁定版本的 Pi Agent Core 接成可替换的 Agent turn 执行引擎。Pi 提供成熟的消息与工具循环，Python 保留多租户产品需要的上下文、策略、工具、证据、副作用和审计边界。

本 Feature 完成后，替换 Agent Engine 不应改变业务工具、SQL schema、审批流程或 Trace 格式。Pi 上游升级也只能影响 sidecar 和协议兼容测试。

## 功能需求

### Product Harness

Python 必须提供稳定的 `AgentEnginePort`，并在调用前组装有界输入；当前实际快照与未决 Context 编译策略见 DC03/DC14。输入只允许包含已验证的组织、Run、Case、任务、事实引用、工具能力和模型配置引用，不接受客户端提供的系统角色、任意工具描述或凭证。

Harness 必须实现以下能力：

- 任务与上下文装配，包含大小上限、事实版本和引用；
- 精确工具注册表、参数 schema、权限与风险检查；
- 模型调用端口，允许确定性 Replay，当前由 F34/F49/F50 接入 Gateway；
- turn 事件、Artifact、工具证据和 checkpoint 写入 F40；
- 取消、超时、协议错误、模型错误和工具错误的稳定分类；
- 业务层终止判断和结果质量状态，不把 Pi 的 completed 直接等同于业务成功。

### AgentEnginePort 与 JSONL 协议

Python 与 Node 使用带版本号的一行一对象 JSONL。协议至少覆盖 turn 启动、模型流式事件、工具调用、工具结果回送、取消、失败和完成。每个事件必须绑定 turn、顺序号和协议版本；未知字段、未知版本、重复或乱序事件、超长行和敏感字段一律失败关闭。

`AgentEnginePort` 可返回有大小限制的可选结构化 output，但不返回未解析模型正文。该字段是 F36 等业务模块的可替换引擎边界。Node 只能将最终 JSON 模型文本通用解析为对象，不实现 Claim 或其他业务 schema；具体结果由 Python 业务模块校验。

协议对象属于 SupplyAgent，不直接暴露 Pi 的内部类。`PiRuntimeAdapter` 负责进程生命周期、协议校验和上游事件映射，Product Harness 只依赖 `AgentEnginePort`。

### Pi sidecar

Node sidecar 必须实际加载锁定版本的 Pi Agent Core，并保留以下上游能力：

- 消息和模型事件循环；
- 多轮工具调用与工具结果回送；
- 流式输出、取消和 turn 终止；
- Pi 能稳定公开且可映射到协议的错误信息。

sidecar 不实现组织权限、上下文检索、工具授权、数据库读取、Proposal、审批或渠道发送。它不得持有 PostgreSQL、渠道或 Provider 原始凭证，也不得提供 shell、文件编辑、终端和任意 MCP 连接。

## 分阶段验收

### P0：受控协议基线，已完成

现有 Python `Harness` 和 `PiRuntimeAdapter` 已通过真实 Node fixture 子进程验证协议 v1、只读 `supply.impact`、工具回送、错误拒绝和 F40 Trace/checkpoint。这个 fixture 没有加载 Pi Agent Core，不能作为真实 Pi 已接入的证据。

### P1：真实 Pi Agent Core，已完成

锁定 `@mariozechner/pi-agent-core` 0.73.1，以确定性 Replay 模型完成一个包含工具调用的 turn。Pi 的 `Agent` 和 tool loop 在 Node 中执行；`tool_execution_start` 被映射为 JSONL `tool.call`，仅由 Python 执行并回传 `supply.impact` 结果。Replay 不访问真实 Provider，Node 不接收 Provider 凭证。`turn.started` 的 `engine` 标记为 `pi-agent-core@0.73.1`，测试断言该标记，旧 P0 fixture 无法单独通过。

### P2：完整 turn 控制，已完成

确定性 Replay 已完成两次 `supply.impact` 往返，并把 Pi `text_delta` 映射为不含正文、只含长度的 `model.delta` Trace。Python 取消会写 `turn.cancel` 并记录 `turn_cancelled`，然后结束短生命周期 sidecar；模型失败、工具失败、异常退出和超时分别映射为 `model_failed`、`tool_failed`、`sidecar_exited`、`timeout`，均写入 F40 Trace。

### P3：产品端口稳定，已完成

一个不导入 Pi 或 Node 的最小 Python JSONL 引擎已通过同一 Harness/工具/Trace 用例。自动化测试还校验 `PI_CORE_ENGINE`、sidecar `package.json` 与 `package-lock.json` 中的 Pi Core 版本一致。F34、F35、F36 和 F41 可只依赖本 Contract 的端口接入。

## 功能边界

F42 不实现 F34 的真实 Provider/BYOK、F35 的 SQL Worker 和崩溃恢复、F36 的 Specialist/RAG、F41 的 Proposal/Execution、F33 的 SSE/Workbench 或 F37 的渠道。上述 Feature 通过稳定端口接入，不能把职责补进 sidecar。

以下 Pi 能力本期明确舍弃：Coding Agent 的 shell、文件系统与终端工具，本地 session/fork/compaction 作为产品事实，扩展和包的任意动态加载，以及 Pi 自带的持久化。以后恢复任何一项都必须单独评估租户隔离、权限、审计和恢复语义。

若真实 Pi 只能靠长期维护私有 fork、把 Provider 凭证交给 Node、在 Node 实现业务策略或依赖本地 session 才能工作，应停止该路线。Product Harness 和 `AgentEnginePort` 保留，后续评估其他 Python 兼容或远程 Agent Engine。

## 当前模型接线

F49/F50 分别复用锁定 Pi 的 Responses/Chat Completions Adapter；不新增通用多厂商转换层。JSONL v1 向后兼容允许 `turn.start.tools[].wireName` 和 `tool.call.modelCallKey`，Python 保留内部名并接收不透明组合调用 ID。最终 output 从最后一条正常完成的 assistant 消息取得，原始 thinking/模型正文不进入公共 Trace。字段约束、私有模型交换与验收见 F49。
