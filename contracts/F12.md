# F12 Contract：证据门控与审批令牌

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度 ｜ 里程碑：M2 ｜ spec：§2.4、§5.5 审批令牌、G2、复杂化 A（A2） ｜ 依赖：F06、F21

## 目标
L3 动作门控（spec §5.5）：代码不规定执行顺序，只在敏感动作前检查前提；前提不满足即拒绝，原因以 `gate_rejected` 交回编排者。提交采购单必须持有主管审批后由代码签发的一次性令牌，并通过提交前重校验（A2：审批期间被买空 → 拒绝提交）。

## 做什么（`src/gate/`，配置 `config/gate.yaml`）
1. **证据门控 `EvidenceGate`**（接入 F21 执行器的同一挂点，取代 `minimal_gate`，最小门控的检查全部保留）：
   - **建草稿**：Decision 对该料有选择（Policy 通过）；**是否替代料由代码判定**——料号不在任何板的 BOM 里即为替代料（不看模型给的字段）。替代料须有本案有效的 `VerificationReport`（`content.candidate` = 该料），等级字段不得是不可信标签（F13）：A 级通过；B 级还须 H1 工程师确认记录；C 级永远拒绝。原料号换供应商不需要验证报告。
   - **送审**：草稿有效且上述证据仍成立。
   - **提交**：以上全部 + 有效审批令牌 + 提交前重校验通过。同一草稿已提交过时按幂等重放放行（环境侧去重，F15 两步写再细化）。
2. **审批令牌**（`approval.py`）：
   - `HumanDesk`：人工节点的代码入口（F25 Web、F05 模拟人工调用）。`approve_po(草稿, by)` 写 `human_decision`（H2）事件，校验存在对应送审且草稿内容哈希一致，再由 `ApprovalVault` 签发令牌并写 `approval_granted` 事件（不含令牌值）；`confirm_substitute(验证报告, by)` 写 H1 确认；`reject_*` 写拒绝。
   - 令牌 = HMAC(草稿 ID + 版本 + 内容哈希 + 到期模拟日 + 审批事件号)，存在进程内保管库，只由执行器按草稿查验；不进模型上下文、事件、日志与追踪。草稿任何改动都产生新版本 → 旧令牌对不上。到期天数来自配置。
   - 密钥取环境变量 `SUPPLYAGENT_APPROVAL_KEY`；没配置时用进程内随机密钥（进程重启后须重新审批）。`rebuild(session)` 按事件与同一密钥恢复保管库。
3. **提交前重校验**：以 Procurement 执行器身份（F11 令牌）经代理层**跳过缓存**实时查该分销商报价（注入照常叠加）：库存须仍能覆盖数量、单价与草稿快照的偏差不超过配置容差。不通过则拒绝，原因写明变化（如"element14 库存 300→0"），并对该报价写外部数据失效（F06 传播使 Decision、草稿失效，编排者须重规划、重新送审）。代理层增加代码专用参数 `fresh`（模型调不到）。
4. **预演**：送审时在环境状态副本上执行这次提交，把"提交前 / 后"的缺料颗数、预计停线天数、预计延期天数附在 `approval_requested` 与给主管的 `human_request` 上（真实环境不变）。
5. **上报计划员门控**：`report_to_planner` 必须引用本案有效的 `ImpactReport`；理由文本里出现的数字必须都能在该 ImpactReport 中找到，否则拒绝并写 `gate_rejected`。
6. **消融开关**：`presubmit_revalidation`——false 时提交不做重校验（spec §3.6 所列），其余门控是 G2 底线不设开关。

## 不做什么
- 引用校验（F23）、知识库 B 写入门控（F20）、Web 审批页与登录（F25）、模拟人工应答规则（F05）、意图 / 完成两步写（F15）、审批后唤醒案子（F10）。
- datasheet 版本比对：由 F06 失效传播使依赖旧版本的验证报告失效，门控只认有效报告。
