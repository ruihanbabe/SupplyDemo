# F49：复用 Pi 的 OpenAI Responses 接入与观测关联

状态：2026-10-23 用户确认实施；代码与本地验证已完成，等待用户验收；业务库迁移尚未应用。本 Feature 提供 OpenAI Responses；F50 提供当前 GLM Chat 兼容路径，Replay 保留。引用 spec §0.3、§2.2–§2.6、§4；承接 F34/F42/F45/F47，不实施审批、渠道或 Mem0。

## 后续选型（2026-10-23）

用户随后选择免费 GLM，并明确使用 OpenAI 兼容 Chat Completions；当前实现及真实证据由 F50 管理。F49 负责 Responses 验收，F50 扩展 GLM 兼容接入；权限和观测边界共同保留。

## 已确认职责

Pi 0.73.1 内置 Responses Adapter 负责 Context/消息、工具定义、原生 Items、流式参数与签名往返；不重写多厂商转换器。Python Gateway 负责单 Run 能力、凭证、策略、请求校验、原生 Responses 转发和计量。Python Harness 负责角色工具授权、业务 Observation、Claim 和持久运行。

当前 Gateway 保留 Responses 与 F50 的 GLM Chat 路径，按服务端策略选择。Node 只拿短期能力，不拿 OpenAI Key。默认不开真实调用；问答入口仅在显式启用并指定有效组织模型策略时接受 gateway 模式。

## 数据与格式

- 工具内部名和合法函数别名一一映射；Python 保有注册定义，Node 将原始 Pi 调用 ID 原样传回，禁止破坏 `call_id|item_id`。
- Invocation、模型调用序号、call key、response ID、工具调用 ID 与 Observation 明确关联；重复调用不得按工具名猜测对应。
- Pi 最后一条 assistant 产物用于业务 JSON 解码，中间解释不拼入最终 JSON；错误、取消、截断不能当正常完成。
- 模型描述从受认证 Gateway 取得；不继承 Replay 的虚假上下文窗口/输出配置。模型策略变化时不得无声改用另一配置。
- 私有模型交换记录保存受限实际请求、策略快照、原生最终响应及状态/摘要；公共 Trace 仅存脱敏关联号、状态、大小和哈希。私有记录缺失时不得宣称完整回放。
- 原始响应与业务 Claim 分离；Pi 版本、Responses 协议和工具别名版本可追溯。保留特殊签名为不透明状态，不当业务证据或公开推理。
- 未取得可信 usage 的中断保留预算预留；取得 usage 后按确定性口径结算，缓存输入与普通输入分开。停止状态与计费状态分离。

0027 追加清单：model_policy 增加 reasoning/context_window/缓存输入价格；新增 worker 私有 model_exchange，绑定预算 reservation 与 Invocation/模型调用序号。工具关联复用 intelligence_observation.payload 的 execution 字段，不建立第二套业务观测表。仅在克隆库应用，业务库仍待确认后统一迁移。

## 验收

固定 Responses SSE → 真实 Pi → Python 工具 → Responses 再请求 → 结构化业务输出；模型策略/凭证覆盖、篡改/未授权工具拒绝；组合调用 ID 保持；中间解释与最终 JSON 分离；参数分片、截断、失败、中断、未知 usage；PostgreSQL/RLS 下私有交换与业务观测关联、不同组织/操作者不可读。原 F45/F47 Replay 兼容。

新能力开关默认关闭；不安装额外框架或升级 Pi；不付费调用、不修改前端或业务库。完成后明确区分“可开始受控真实联调”和“真实模型已验收”。

## 配置与受控真实联调

1. 用户确认后按顺序应用 0024–0027；本轮 Makefile 的 f49-migrate 仅应用 0027，不应用 F41 草稿。
2. 创建组织的 OpenAI model_policy：精确 model_id、context_window、reasoning、max_output_tokens、普通/缓存输入及输出价格、单次预留上限和日预算；真实调用前确认价格与模型能力，不使用演示默认值冒充。
3. Python 部署注入 `SUPPLYAGENT_MODEL_SECRET_<credential_ref>`；至少 32 字节 Gateway 签名密钥；Worker 配置组织、actor、owner，成员须 maintainer 且 scope.runtimeWorker=true。旧 SUPPLYAGENT_LLM_* 不用于这条路径。
4. Gateway 地址为 `http://127.0.0.1:8001/v1`（按实际私有地址配置），使用现有 gateway-run、runtime-worker、api-run；真实模式不使用 Worker Replay。
5. 单独确认付费预算/调用范围后，开启组织策略 real_calls_enabled 和入口 SUPPLYAGENT_RESPONSES_ENABLED=1；问答指定 mode=gateway、model_policy_id。先一条商机调查，检查原生响应、五角色 Claim、引用、unknown、费用和私有记录，再做小规模业务质量评测。

Gateway 提供模型描述、Responses 与 F50 Chat Completions 路由。无新增服务、依赖或自动重试层；Pi/HTTP SDK 重试关闭，重试仍由持久 Runtime 管理。关闭入口只暂停新请求，已接单模式不降级。私有模型正文仅记录访问受限的请求/最终响应；没有逐分片归档，不声明逐字节 SSE 回放或完整 F38 已完成。

组件准入：需要补齐评测归因与模型配置；复用 Pi/F34/F35/F40，不引入新框架；成本为一张私有表和三个策略字段；通过真实 Pi、固定 Responses、RLS 与失败/计费测试验证收益。新增入口默认关闭。记录租约中断时可能停留 running，不能仅凭该状态判断调用未计费，应结合 reservation/usage 对账。


## 代码与数据落点

- `gateway.py`：本 Feature 的 Responses Provider/Replay，模型描述与策略指纹，原生 SSE 转发，缓存计费，私有交换登记；结算与最终响应在同一数据库事务完成，失败不伪装为业务成功。
- `model_tools.py` / `harness.py` / `f42_protocol_sidecar.mjs`：固定函数别名，保留组合 ID，通过 ContextVar 将调用身份传给工具，拒绝重复 ID，最终 assistant 解码。
- `intelligence.py` / `app.py`：受控模型入口、实际 prompt hash/Context 策略及引擎版本快照，Observation.execution 关联。
- `0027_f49_responses.sql`：三个策略字段、单组织模型行锁函数、一张 RLS 私有交换表及一次性定稿约束；不授予 API 任意修改 model_policy 的权限。
- `tests/test_product_api_gateway*.py` / `test_product_api_responses_integration.py`：MockTransport、本地原生 Responses fixture 与真实 Pi/SQL/RLS；不是付费模型结果。
