# F41 Contract：受控副作用迁入，工具、权限、Proposal、审批令牌、执行账本与恢复

> 状态：草案，等待 F35/F42 ｜ 类型：深度 ｜ 里程碑：M3 ｜ spec：§2.7、§2.8、§3.1 ｜ 依赖：F31、F35、F42、F07、F11、F12、F13、F15

## 目标

将旧采购门控扩展成所有产品副作用的统一 Execution 链。客户字段更新、采购提交和渠道发送的安全性不依赖 Agent prompt、浏览器状态或单次人工点击。

## 2026-10-10 架构约束

Tool Proxy、Proposal/Approval 状态机、令牌复核、Execution ledger 与 R2 Adapter 都由 Python API/Worker 实现。Pi sidecar 只能提出工具调用，Python Product Harness 完成授权和分派；Pi 与 Next 均不得获得执行令牌、直接调用渠道或写业务表。

## 做什么

1. 统一 Tool、Proposal、Approval、Execution 和 Send/PO Ledger 的状态及幂等键；Proposal 固定组织、目标对象版本、内容哈希、证据、风险级别、有效期和请求者。
2. 改造 F07/F11/F12：Pi 只能调用经过组织 scope、能力令牌、风险等级和参数 schema 检查的工具；R1 只生成 Proposal，R2 只能由 Worker 执行。
3. 改造 F13：不可信内容不能流入客户字段、采购内容、Policy 数值、长期记忆、出站 URL 或发送正文；对外文本保留来源标记。
4. 改造 F15：执行前重校验组织权限、草稿哈希、目标版本、审批有效期、opt-out、service revision；执行意图/完成两步写并恢复，重复投递恰好一次。
5. 接入 F14/F21：拒绝、过期、下游失败或提交后失效转成反馈/升级，采购执行器成为该统一链上的一个 R2 Adapter。

## 不做什么

- 不自动批准、不自动绕过 opt-out，也不把 ready_for_review 当作执行授权。
- 不实际调用渠道或真实供应商，除非相应 F37/G5 集成已获授权。

## 验收证据

| 检查 | 通过条件 |
|---|---|
| 门控测试 | 未审批、草稿变更、权限变化、过期令牌、污点字段、opt-out 均不可执行。 |
| 幂等恢复 | 采购提交和渠道发送在意图前后崩溃、Job 重投、重复回调时都至多执行一次，账本和 Trace 完整。 |
| 回归测试 | 原采购草稿/审批/提交的证据门控不被 CRM Proposal 扩展削弱。 |

## 当前进度（2026-10-19）

F07、F11、F12、F13 和 F15 提供单租户历史资产，统一多租户 Proposal/Execution 模型尚未实现。当前 F42 只开放只读工具，本 Feature 开工前不会向 Agent Engine 暴露 R1 或 R2 动作。
