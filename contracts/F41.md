## 目标

按 BL10 建立所有产品副作用的统一 Execution 链；旧采购实现已移除，不能声称仅需接线。客户字段更新、采购提交和渠道发送必须由受控授权和执行前校验保证。

## 2026-10-10 架构约束

Tool Proxy、Proposal/Approval 状态机、令牌复核、Execution ledger 与 R2 Adapter 都由 Python API/Worker 实现。Pi sidecar 只能提出工具调用，Python Product Harness 完成授权和分派；Pi 与 Next 均不得获得执行令牌、直接调用渠道或写业务表。

## 做什么

1. 统一 Tool、Proposal、Approval、Execution 和 Send/PO Ledger 的状态及幂等键；Proposal 固定组织、目标对象版本、内容哈希、证据、风险级别、有效期和请求者。
2. Pi 只能调用经过组织 scope、能力令牌、风险等级和参数 schema 检查的工具；R1 只生成 Proposal，R2 只能由 Worker 执行。
3. 不可信内容不能流入客户字段、采购内容、Policy 数值、长期记忆、出站 URL 或发送正文；对外文本保留来源标记。
4. 执行前重校验组织权限、草稿哈希、目标版本、审批有效期、opt-out、service revision；执行意图/完成两步写并恢复，重复投递恰好一次。
5. 拒绝、过期、下游失败或提交后失效转成反馈/升级，采购执行器成为该统一链上的一个 R2 Adapter。

## 不做什么

- 不自动批准、不自动绕过 opt-out，也不把 ready_for_review 当作执行授权。
- 不实际调用渠道或真实供应商，除非相应 F37/G5 集成已获授权。
