# F34 Contract：组织级 Model Gateway / BYOK、预算、成本与审计

> 状态：实现完成，等待用户验收｜类型：深度｜里程碑：M2｜spec：§0.3、§2.4、§4

## 目标

由 Python Gateway 实现组织策略、凭证引用、预算预检、Provider 调用、计量和失败分类，再通过模型端口服务 F42 Product Harness。Next 只读取脱敏投影。

## 保留基础

`supabase/migrations/0009_f34_gateway.sql` 与 `supabase/tests/f34_gateway.sql` 保留为组织 RLS、预算、凭证引用和计量 schema 的基础。表中只允许不可解释的 `credential_ref`，不存 BYOK 原文。

## 已实现

- Python 私有 HTTP Gateway 校验短期、单 Run 的签名能力；模型策略、Provider 和真实凭证只在 Python 解析。Pi 通过 Gateway 的 OpenAI Chat Completions 流式接口调用，不得到原始 BYOK。
- SQL 在调用前锁定模型策略并预留单次最高费用，按策略的 UTC 日预算计费；调用结束后用 Provider usage 做整数费用结算，只保存摘要哈希、token 数、费用和结果。预算拒绝写入审计。重复 call key 被拒绝。
- OpenAI Provider Adapter 从服务端 `credential_ref` 解析注入的环境凭证，并强制使用策略中的模型与输出上限；默认无签名密钥时 Gateway 拒绝启动，真实调用还须策略显式开启。Replay Provider 供固定样例测试。
- Pi 子进程环境改为白名单，仅额外传单 Run Gateway 地址与短期能力；F42 Replay 默认路径仍可运行。

## 待独立验证或后续接线

- 真实 OpenAI 付费请求/BYOK 的端到端验证仍需 G5 单独授权；当前只用本地 HTTP MockTransport 验证 Adapter 的地址、凭证与模型覆盖行为。
- F35 Worker 已在领取带模型策略的 Job 后签发单 Run 能力并配置 Pi Adapter；Replay 的 Worker 全链路已验证，但 Worker→真实付费 Provider 尚未演练。
- Anthropic/custom Provider 尚无适配器，策略存在时安全拒绝。流中断而 Provider usage 不可得时保留预算预留，待人工对账；不以零费用释放可能已计费的请求。

## 边界

- 凭证不进入模型、事件、Trace 或前端。
- 真实 Provider、BYOK 和付费请求默认关闭。
- 模型不可任意选择 Provider、读取组织配置或修改预算。

## 与 F42 的接口

F42 P1 使用确定性 Replay 模型。用户在 2026-10-19 选择单 Run 短期 HTTP 能力；Gateway 决定 Provider、凭证、配额和审计，Node 只拿到签名能力，不拿原始 BYOK。
