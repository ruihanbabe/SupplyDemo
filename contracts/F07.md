# F07 Contract：工具代理层与 MCP Server

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度② ｜ 里程碑：M1 ｜ spec：§5.4、§4.3、G1、G5 ｜ 依赖：F03、F06

## 目标
Agent 只与代理层交互（G1）。代理层对每次工具调用按固定管道执行（spec §5.4）：白名单 → 参数校验 → 查缓存 → 配额 → 调用 → 返回校验（B3）→ 注入叠加（§4.3）→ 留档 → 裁剪 → 记事件，统一返回格式。

## 做什么（`src/tools/`）
1. **Server 与工具定义**：进程内 Server，接口按 MCP 的工具形状（`name`、`description`、`inputSchema`；`list_tools` / `call_tool`）。每个工具声明：参数模型、来源（模拟 / 外部）、提供方（配额键）、真实时间缓存 TTL、模拟时间有效期、返回校验器。
2. **Server**
   - 环境（类 ERP，只读，spec §5.4）：查库存、查采购单、查运单、查工单、查订单。数据来自 F03 `Environment`；不缓存（环境按模拟日变化）。没有任何写工具、改计划或改工单的工具（G8）。
   - 分销商：查报价（多料 × 多家）。后端可替换；本 Feature 只实现**固定样例后端**（按料号与分销商确定性生成库存、价格阶梯、交期，保留原文值与归一化值），真实 DigiKey / Mouser / element14 后端等用户授权（G5；旧适配器 `976bb17` 只作参考）。
   - 留档：按记录号读原始返回，支持游标翻页，不产生外部调用。
   - 编排控制（仅编排者）：派任务、提出目标修订、上报计划员、问用户、结束本段——本 Feature 只定参数模型并把调用转交给注册的处理函数（语义由 F09/F22 实现）。
   - 参数 Server 推迟到 M2，与 F19/F23 一起做（它的数据源 DigiKey 参数检索需真实调用授权）。
3. **统一返回**：`{ok, data, truncated, next_cursor, source{provider, fetched_at, valid_until, record_id}, warnings, error}`；错误类型：参数错误、查不到、限流、超时、上游错误、返回格式异常、无权限、门控拒绝、超预算，各带能否重试与处理提示。
4. **两个时钟**：缓存按真实时间（Redis，键 = 工具 + 参数哈希，TTL 过期）；有效期按模拟日（`fetched_at` + 有效天数）。缓存里存原始数据，注入每次调用时现叠加。
5. **配额与限流**（Redis）：每个提供方日计数 + 令牌桶（Lua 脚本原子扣减）；超限返回"限流"错误。同一组件实现 F08 的 `Limiter` 接口，供模型端点复用。离线测试用内存实现，集成测试用真实 Redis。
6. **返回校验（B3）**：缺失字段置为"未知"并加警告"不要自行推测"，整体无法解析返回"格式异常"。
7. **多源矛盾（B2）**：代码工具函数：同一参数多个来源差异超过容差时加警告，各来源值分开返回、不合并。参数 Server 推迟，本 Feature 只提供函数与测试。
8. **留档**：每次非缓存调用的原始返回与叠加后返回都存（`tool_record` 表，迁移 `0004_tool_record`；离线用内存实现），记录号写进 `source.record_id` 与事件。
9. **裁剪**：列表默认 10 条，游标翻页（游标指向留档，翻页不再调用上游）。
10. **事件**：每次调用写 Session 事件 `tool_call`（工具、参数、是否命中缓存、记录号、错误类型、警告），实体键取自参数与结果。
11. **注入挂点**：`overlays`（F04 注入 B/A 类外部数据异常）与 `faults`（F18 测试注入超时、限流、上游错误、格式异常）两个挂点，本 Feature 只留接口与测试。
12. **消融开关**：`tool_return_validation`、`source_conflict_warnings`。

## 不做什么
- 能力令牌、代表链、作用域检查（F11）：本 Feature 的白名单是"执行者 → 允许工具名集合"的最简检查，接口留给 F11 替换。
- 重试退避与熔断（F15）；计量汇总（F17）；真实分销商调用。
- MCP 标准 stdio / HTTP 传输：需安装 `mcp` 包（新依赖，需用户同意）；接口形状已对齐，届时加一层薄包装。
