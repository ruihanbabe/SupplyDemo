## 验收与消融

- 同一故事初始快照稳定识别 T1 逾期、缺未来任务；D+1 新增 T2 后只消除对应缺口，T1 不自动完成。
- 无权限读取的任务不能推断为不存在；可见范围不足显式未知。
- 多零件计算覆盖三种物料，只有 RF 为 200 缺口；分销商报价不进入确认收货。
- 实际 HTTP → Job → Pi Replay → 私有 Observation，保存 as_of、节点输入和实际结果；同键不同 as_of 拒绝。
- 0025 可重复应用；同组织成员约束与跨组织拒绝；旧 F45 运行仍工作。
- 消融 SUPPLYAGENT_BUSINESS_NODES_ENABLED=0（默认）：新请求沿旧 F45；1 启用新节点。已接单的新任务仍按绑定模式运行。
- make check、make f46-integration-test；无真实模型、供应商、渠道调用，无业务库迁移。

准入：缺少可计算的业务事实阻断故事；复用既有数据库、F39 计算与 F45 工具，不增加服务或依赖；代价是四个字段与一条版本化配置；收益由模拟场景和真实 PostgreSQL/Pi 链路验证。

- `data/scenarios/electronics/initial.json`：明确标记 synthetic 的三个客户、会话、任务及三种物料输入；产品/BOM、报价、替代的尚未映射项单列，不伪装领域模型已完成。
- `tests/test_product_api_business_nodes_integration.py`：可重置的临时克隆库种子加载和场景推进；禁止对业务库执行种子。后续部署种子命令另行确认，本轮不提供无保护的业务库导入入口。
- `src/product_api/business_nodes.py`：版本化策略读取、跟进信号、固定范围的多零件计算；这些是 Python 确定性节点，不额外启动 Agent。
- `src/product_api/app.py`、`runtime.py`、`intelligence.py`：新请求模式/时钟/完整范围绑定、Worker 重建、实际工具输入输出与旧运行兼容；新增分析时间拒绝无时区值，关闭入口时不能静默忽略显式时间。
- `supabase/migrations/0025_f46_business_nodes.sql`：四个字段、组织成员外键、新命令；保留旧 F45 命令。
- `config/product/followup-policy.json`：演示策略，不是生产组织政策。配置跟随观测保存，不将语义 prompt 当业务规则存储。
- `tests/test_product_api_business_nodes.py`：四个离线业务行为测试；F45 输入校验测试补充时间与开关行为。

共涉及超过八个代码/数据/文档文件；不增加服务、第三方依赖或前端功能。前端沿用 F45 的证据展开，新增信号通过实际证据摘要显示。

## 已验证的状态语义

1. 第一条调查保存 `task_overdue + no_visible_future_task`，完整 Case 观测包含三个料号；RF 期末投影为 -200，其他两个为正。
2. T2 由外部测试事实推进写入（不是 F41 审批实现）；授权范围内重新调查只剩 `task_overdue`。旧调查的输入和观测不被改写，T1 仍为 open。
3. 主管可见而销售不可见的 T2 不得被销售节点计入下一步；输出始终限定“当前可见范围”。
4. UTC 换日边界仍按配置的 Asia/Shanghai 业务日期计算；这是业务投影时钟，不是历史数据库重建。
5. 接单后关闭新请求开关，不会降级已排队任务。关联 Case 后续追加料号，旧任务不能无声扩大读取范围。
6. 显式 as_of 不同的同键请求拒绝；owner_id 不能关联另一组织的成员。
