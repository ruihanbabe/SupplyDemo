# F08 Contract：模型适配层

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：最小 ｜ 里程碑：M1 ｜ spec：§5.3（弱模型输出可靠性、模型适配层与降级）、§5.11（完整输入输出）｜ 依赖：F06

## 目标
Agent 循环只面对一种内部格式；各家模型（GLM-4.7-Flash 主、Qwen 备）的差异、Schema 校验与修复、降级、编造料号拒绝、完整输入输出留痕都在这一层由代码完成。

## 做什么（`src/models/`）
1. **内部格式**：消息、工具定义、工具调用、模型响应（文本 / 工具调用 / 用量 / 结束原因）。
2. **提供方适配**：OpenAI 兼容请求的组装与响应解析，按 `config/models.yaml` 中每个端点的**差异配置**处理：是否支持并行工具调用、`tool_choice`、JSON 输出方式（`json_schema` / `json_object` / 仅提示）、工具参数返回为字符串还是对象、工具数量上限、工具调用写在正文里（`<tool_call>…</tool_call>`）的兜底解析。传输层可替换：`HttpTransport`（httpx，凭证只从环境变量读、不进请求体与日志，G1）与 `ScriptedTransport`（测试用固定应答）。
3. **校验与修复**（spec §5.3 C3）：结构化输出用 pydantic 模型校验；工具调用校验工具名存在（不存在时报错并附可用工具清单）与参数模型。不通过时把具体错误回给模型**修复 1 次**；仍失败算一次格式失败。
4. **编造料号拒绝**：输出模型中标记为料号的字段（`Mpn` 类型），值必须在调用方给的已知集合里，否则按校验失败处理（进入同一修复流程）。
5. **降级**：执行者 → 模型链写在配置里；主模型格式失败后改用备用模型；备用也失败抛 `ModelFailure`（普通失败，交回上层按 spec §5.8 处置）。传输错误（超时、限流、上游错误）抛 `ModelUnavailable`，重试与熔断归 F15。
6. **完整输入输出记录**：每次尝试写一条 Session 事件 `llm_call`（字段沿用 `gen_ai.*`：模型、端点、请求、响应、token、耗时、第几次尝试、是否修复 / 降级、prompt 哈希），temperature 固定 0（spec §5.12）。
7. **限流挂点**：`Limiter` 接口（默认不限）；Redis 实现归 F07，模型端点复用（features.json F08 备注）。
8. **消融开关**：`schema_repair`（关 = 不修复，首轮不过即算失败）、`model_fallback`（关 = 不降级）、`fabricated_mpn_check`（关 = 不查料号）。

## 不做什么
- 不做任何真实 LLM 调用；测试全部用 `ScriptedTransport`。真实联调等用户授权（G5）。
- 不做重试退避、熔断（F15）、计量汇总表（F17）、全回放传输（F18 基于本层 `llm_call` 记录实现）、prompt / Skill 管理。

| # | 命令 | 通过条件 |
|---|---|---|
| 1 | `make check` | 离线测试覆盖：两种端点差异（参数字符串 / 对象、正文内工具调用）解析成同一内部格式；Schema 不过 → 修复 1 次成功；修复仍失败 → 降级到备用成功；备用也失败 → `ModelFailure`；未知工具名的错误信息附可用工具；编造料号被拒并修复；每次尝试都有 `llm_call` 事件且不含凭证；三个消融开关各自生效 |

## 默认值
- 修复消息格式：`你的上一条输出不合格：<逐条错误>。请只输出修正后的结果。`
- `Mpn` 标记用 pydantic 字段元数据 `json_schema_extra={"x-mpn": True}`。
