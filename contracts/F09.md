# F09 Contract：Runtime（M1 薄版）

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度② ｜ 里程碑：M1（薄版，后续里程碑补全）｜ spec：§5.3、§4.2 ｜ 依赖：F06、F07、F08

## 目标
把"模型 + 工具 + 日志"组织成可挂起、可恢复、有硬预算的执行：一次唤醒跑一个活跃段；编排者成批派任务、整批结束才被唤醒一次；每个模拟日按"推进环境 → 投递事件 → 运行被唤醒的案子 → 全部等待 → 下一天"循环（spec §5.3 调度循环）。

## 做什么（`src/runtime/`）
1. **执行者循环** `ExecutorLoop`：模型调用（F08）→ 工具调用（F07 代理层，身份由 Runtime 标注）→ 结果回给模型 → 直到给出最终输出、预算触顶或失败。子 Agent 与编排者共用。
   - **循环检测**：相同工具 + 相同参数连续第 2 次，不再调用，回"已查过，结果是……"；再犯即强制结束该执行者（记原因）。
   - 格式失败（`ModelFailure`）按普通失败结束；传输失败（`ModelUnavailable`）向上抛（重试熔断归 F15）。
2. **三层硬预算**（默认值写进 `config/harness.yaml` 的 `runtime` 段，G7）：子 Agent 轮数 10、工具调用 12，触顶交回"未完成"Artifact 附原因；编排者每活跃段轮数 12，触顶结束本段并记录；案子重规划 3 次、LLM 调用总数上限，触顶**升级给人**并以"已升级"关闭。案子级计数从事件日志投影（崩溃后不丢）。
3. **派发与汇合**：编排控制工具 `dispatch_task` 在一轮里可出现多次，同一轮的派发组成一批；批内逐个运行子 Agent（见下"默认值"），每个任务产出一个 Artifact（成功或"未完成"），整批结束后写一条 `batch_joined` 事件并把汇总一次性交回编排者。
4. **活跃段**：唤醒 → 从日志与 Artifact 重建编排者上下文（M1 用最小构建器：案子卡片 + 有效 Artifact 摘要 + 本次唤醒原因；完整分区组装归 F16）→ 编排者循环 → `end_segment(wait_for=…)` 或所有任务都在等外部结果 → 案子进入等待。进程内不保存半截对话；段中崩溃则整段重跑（工具结果已留档，多数命中缓存）。
5. **调度循环** `Scheduler.run_day()`：推进环境并把当日事实写成 `env_day` 事件 → 交给路由挂点（F10 实现；默认不唤醒任何案子）→ 到期定时器唤醒 → 按固定顺序运行被唤醒的案子，**同时活跃的案子数有上限**，超出的排队（`case_queued`）并在后续轮次运行 → 没有待运行案子时本日结束。Agent 思考不消耗模拟时间（§4.2）。
6. **定时器**：`timer_set` 事件（案子、到期模拟日、原因），到期即唤醒。
7. **消融开关**：`loop_detection`、`batch_join`（关 = 每个任务完成都立即唤醒编排者一次）。

## 不做什么
- 路由、订阅、开案、合并（F10）；编排者的计划、节点库、模板、目标修订（F22）；上下文完整分区与裁剪（F16）；反馈卡片与重规划分级（F14）；重试熔断与意图/完成两步写（F15）。
- 真实线程 / 进程级并行（见默认值）。

## 默认值（请验收时确认）
- **批内与案子间按固定顺序依次执行，不用真实线程**：线程并行会让事件交错顺序不确定，破坏 spec §0.2 可复现与 §5.12 全回放哈希链比对；而 Agent 思考不消耗模拟时间（§4.2），顺序执行不改变结果，只是更慢。"并行派发与汇合"的语义（成批派发、整批结束才唤醒一次、部分失败一并交回）与并发上限都保留。若要真实并行，需在 F18 回放时按任务号重排事件，届时再议。
- 编排控制 `end_segment` 增加必填 `wait_for`（human / arrival / external），用于进入等待状态（F07 参数模型随之修改）。
