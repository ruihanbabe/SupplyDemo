# F19 Contract：datasheet 知识库 A

> 状态：已写，按用户 2026-09-30 指示"用固定样例"直接实现、事后统一验收 ｜ 类型：深度 ｜ 里程碑：M2 ｜ spec：§6、§6.1、§6.2、§5.5 出站网络控制、§2.4 引用校验 ｜ 依赖：F06、F07

## 目标
datasheet 按页存储、按页检索、按页引用（spec §6.1），版本 = 内容哈希，新版本入库触发失效传播（§6.2）；下载只走出站白名单（§5.5）。本 Feature **只用固定样例，不做任何真实下载**。

## 做什么（`src/datasheets/`，迁移 `0007_datasheet`，配置 `config/datasheets.yaml`）
1. **存储**：`datasheet_version`（料号、版本哈希、来源 URL、标题、目录、取得日，旧版本保留）与 `datasheet_page`（料号、版本、页码、页文本 Markdown、`tsvector` 生成列 + GIN 索引），只追加；授予 F11 只读角色 SELECT。离线用内存实现、集成用 Postgres，接口一致。
2. **获取**（`fetch.py`）：来源接口两个实现——`FixtureSource`（`tests/fixtures/datasheets/` 下的合成样例，非真实 datasheet 内容）与 `HttpSource`（每一跳过 F11 `datasheet` 出站策略：HTTPS、白名单域名、禁内网、重定向检查、大小上限、只收 PDF）。`HttpSource` 只用离线模拟传输测试，本 Feature 不发真实请求；原始文件落 `data/datasheets/`（不进 git，已加入 `.gitignore`）。
3. **解析**（`parse.py`）：解析器接口；`FixtureParser` 读样例的逐页 Markdown 与目录；`DoclingParser` 惰性导入 Docling，未安装时报"尚未具备：需安装 docling（新依赖，需用户同意）"，不静默成功。
4. **入库**（`Ingestor.ensure(mpn)`）：某料首次进入案子时按需获取（不预取）→ 版本 = 内容哈希 → 与最新版本相同则不动；不同则解析入库、写 `datasheet_ingested` 事件，且已有旧版本时对外部引用 `datasheet:<料号>` 写失效（F06 传播使依赖旧版的 VerificationReport 失效）。`refresh(mpn)` 供提交前重校验与 A5 注入（F04）检查版本。
5. **检索**：关键词 + 同义词扩展（配置里的种子同义词，F20 术语表接入后替换）定位页码，返回页码与片段；Postgres 用全文检索，内存实现按词频，排序规则一致（得分降序、页码升序）。
6. **datasheet Server**（R0，按料号作用域 `scoped`，F11 可限定 Verifier 只读两颗料）：`find_datasheet(mpn)`（触发按需入库，返回版本、页数、标题）、`datasheet_toc`、`datasheet_search(mpn, query)`、`datasheet_read_page(mpn, page, version?)`。
7. **引用校验器**（`cite.py`，spec §2.4）：给定（料号、版本、页码、引用数值 / 原文片段）检查版本与页真实存在、数值出现在该页原文（数字规范化比较）、片段逐字出现；不通过返回原因（F23 据此降级为"无法确认"，通过后用 F13 `mark_verified` 去污）。
8. **提交前版本检查**：F12 证据门控可选接入 `refresh`——替代料提交前刷新其 datasheet，出新版本即失效传播，门控因报告失效而拒绝（spec §6.2 三个检查时机之一）。
9. **消融开关**：`datasheet_synonyms`（false 时检索不做同义词扩展，对比召回）。

## 不做什么
- 真实下载与真实 PDF 解析（需用户授权与 Docling 依赖）；向量检索、图表识别（spec §6.1 本期不做）；术语表本体（F20）；A5 叠加改动生成新版本（F04）；Verifier 使用这些工具（F23）。
