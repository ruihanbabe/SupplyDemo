# F01 Contract：工程底座

> 状态：已确认（2026-09-29） ｜ 类型：最小 ｜ 里程碑：M1 ｜ spec：§1.3、§5.1 存储 ｜ 依赖：无

## 目标
在一个干净的仓库里恢复能跑的工程底座：`make check` 全绿，空库迁移后只剩 v0.3 需要的表，`hw_part` 能从原理图原始文件重新生成。后续所有 Feature 都在此之上开工。

## 现状
- `src/` 在 v0.2 重置时整体删除；现有 3 个测试 import 已删除的模块（`knowledge.*`、`persistence.build_hardware_parts`、`infrastructure.database`），目前跑不通。
- alembic 0001 建了 22 张 v0.1 表（`run_state_event`、`business_rule`、`demand_line` 等），v0.3 一张都不用；0002–0006 在其上反复增删。
- Makefile 里 `import-data`、`probe-suppliers`、`explain`、`seed-rules`、`seed-supply`、`model-smoke`、`run`、`health` 指向已删除的代码。

## 做什么
1. **从 git 历史恢复 `hw_part` 管线**（取自 `8342d20^`）：`src/knowledge/{fetch,kicad,parts,prune}.py`、`src/persistence/build_hardware_parts.py`、`src/infrastructure/database.py`、`config/knowledge/sources.yaml`（只保留 hackrf-one 条目）。只恢复这几个文件，内容按原样，只修与已删模块的 import 断点。
2. **迁移压缩成新基线**：删除 0001–0006，新 `0001_baseline` 只建 `hw_part` 表与应用数据库角色 `supplyagent_app`（hw_part 只读授权）。旧迁移在 git 历史中可查。
3. **Makefile 对齐**：保留并确保可用的目标——`help`、`setup`、`status`、`freeze`、`compile`、`lint`、`test`、`check`、`test-integration`、`services-up/status/smoke/down`、`migrate`、`fetch-hardware`、`prune-hardware`、`build-parts`；指向已删代码的目标删除。按 Makefile 自身约定，暂不可用的目标要明确报"尚未具备"，不能静默成功。
4. **测试恢复**：现有 3 个测试跑通；`test_schema.py` 改为断言新基线（只有 `hw_part` 与 `alembic_version`）。
5. **新建仓库 `AGENTS.md`**（§0.5，≤100 行）：命令入口、硬约束、协作规则；只写编号引用（spec §x、G1–G8），不复制 spec 正文。
6. **包结构**：`src/` 只建本 Feature 用到的包（`knowledge`、`persistence`、`infrastructure`），其余模块由各自的 Feature 创建。

## 不做什么
- 不建任何 v0.3 业务表（事件日志、Artifact 等归 F06）。
- 不写新功能代码，不引入新依赖。
- 不动 `compose.yaml`（Redis 保留，用途见 spec §5.1）、`CODING_RULES.md`、`requirement.txt` 的旧文档契约（它们引用已删除的旧文档，登记到 HANDOFF 已知问题，另行处理）。
- 不联网：验收只用仓库内已有的 `data/hardware/raw/hackrf-one`；`fetch-hardware` 恢复但不在验收中执行。
- 不处理第二块板（F02）。git 历史里有 `bms-c1`、`jetson-agx-thor-baseboard` 两块板的原始文件，留给 F02 选型时参考。
