# F20 Contract：知识资产与知识库 B

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：最小 ｜ 里程碑：M2 ｜ spec：§6、§6.3、§5.10、§3.5 ｜ 依赖：F01、F06

## 目标
把替代判断的真值来源与注入内容落地：术语表、比对清单、Skills、板级文档作为知识资产；知识库 B（替代关系、料号别名）只收人工确认的条目（G3），按实体键注入、依赖变化即待重验、可按案子一键撤销。

## 名称修正
`features.json` 中本项名称的"板级上下文 YAML"与 F02 已定的"README 原文存档、不预先结构化"冲突，改为"板级文档原文与文档工具"（F02 第 2 步、spec §6 表）。

## 做什么
1. **术语表**（`config/knowledge/glossary/<品类>.yaml`，5 个品类：射频开关、射频综合器、电容、电阻、LED，每类约 20 条，mock 业务知识）：每条 = 术语、同义写法、一句说明。`Glossary`：按关键词匹配注入（节点启动时由 F22/F23 调用，每次上限在配置）；`synonyms()` 供 F19 检索同义词扩展（替换 F19 的种子同义词）。
2. **比对清单与替代规则**：补齐另三个品类的清单（`config/checklists/`，格式同 F21）；料号 → 品类映射（`config/knowledge/categories.yaml`，按料号前缀，代码匹配）。
3. **Skills**（`skills/<名>/SKILL.md`，spec §3.5 四个：PartAnalyst、替代料评估、Explainer、目标修订判断）：`load_skill(name)` 返回正文与哈希（运行清单用）；强制加载 / 自选加载归 F22/F23。
4. **板级文档**：README 原文按标题切页，以文档键 `board:<板>` 进 F19 页表，与 datasheet 共用四个文档工具（原文只读、不结构化）。
5. **知识库 B**（`src/knowledge_base/`，迁移 `0008_kb`：条目表 + 状态变更表，都只追加；离线内存实现、集成 Postgres）：
   - **种子导入**：原理图 `Substitution` 字段，"any equivalent" 丢弃；其余解析为（厂商, 替代料号），带板与位号适用范围，状态"未验证种子"（替代检索可列为候选，门控不认，spec §6.3）。
   - **提议**：编排控制新增 `propose_memory`（R1，S1 可用）：替代关系引用 VerificationReport，别名给出说法与料号；写 `memory_proposed` 并通知对应人工节点（替代 → H1 工程师，别名 → H3 采购员），提议数量不限；每条记来源案子、证据与外部数据依赖（到版本）。
   - **确认落库**：`confirm(提议, by, 节点)` 只接受对应节点的确认，经 F13 长期记忆汇点检查（必须有确认记录、不可信文本只以引用块存放）后写条目。
   - **失效**：依赖的 datasheet 出新版本 → 相关条目"待重验"；料号 EOL 事件（F04 产生）→ 涉及它的条目标记；来源案子判定被投毒 → `revoke_case(案子)` 一键撤销其衍生的全部条目。路由每日同步（F10 `CaseRouter` 可选接入）。
   - **使用**：代码按实体键（料号、品类、板）匹配后注入上下文，每次最多 5 条并标明来源与状态；F16 编排者上下文新增 `[记忆]` 分区（可选接入）；替代检索子 Agent 另有只读工具 `kb_substitutes(mpn)`（按料号作用域）。不给模型通用"查记忆"工具；门控与 Policy 不读记忆。
6. **消融开关**：`memory_injection`（false 时不注入记忆分区）、`glossary_injection`（false 时术语不注入）。

## 不做什么
- Resolver 三层与别名消歧流程本身、Verifier 与替代检索子 Agent（F23）；H1/H3 的 Web 页面（F25）；EOL 等业务事件的产生（F04）。
