# F03 Contract：环境内核

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：最小 ｜ 里程碑：M1 ｜ spec：§4.1、§4.2、§4.6、§1.3 模拟环境 ｜ 依赖：F01

## 目标
一个按天推进、可用种子复现的模拟工厂：给定两块板的计划与订单，货到入库、开工领料、缺料停线、订单到期都由机制自动发生；外部只能经查询接口读、经写入接口下采购单；任意一天可以快照、分叉、崩溃后恢复；运行结束给出环境侧结果指标。它是 Agent 操作的唯一业务状态来源（spec §5.1"环境状态"）。

## 架构（用户 2026-09-29 定：方案 A）
纯 Python 内存领域模型按天推进；Postgres 只存两张表：`env_snapshot`（每日整状态 JSONB + 哈希）与 `env_write`（外部写入只追加日志 + 幂等键）。崩溃恢复 = 载入最近快照 + 重放当日写入；分叉 / 预演 = 载入快照。

## 做什么（五小步，每步单独提交）
1. **领域模型 + 日推进**（`src/simenv/`，纯内存、离线测试）
   - 对象（spec §4.1）：客户订单、工单、库存（在库 / 预留；在途由运单推出）、采购单（环境只管 已提交 → 已发货 → 已到货；草稿与审批中属 Harness 侧 Artifact，归 F06/F12）、运单、产线。
   - 每日顺序（spec §4.2）：① 注入挂点（F03 只留空挂点，异常由 F04 填）② 运单到期到货入库，采购单转"已到货"③ 已提交采购单按供应商备货天数转"已发货"并生成运单 ④ 在制工单到完工日完工，成品计入订单、腾出产线 ⑤ 按开工日先后重算预留 ⑥ 到开工日（或此前缺料停线）的工单一次性领料：料齐则开工，缺任一料则整单停线、次日重试 ⑦ 订单到期检查，未交齐则按天累计延期直至交齐。
   - 推进本身不含随机数；同一初始状态 + 同一写入序列 ⇒ 同一结果。时钟"所有案子都在等待才推进"由 Runtime（F09）控制，F03 只提供 `advance()` 推进一天。
2. **按种子生成初始状态**：从原始层原理图（经 MANIFEST 校验，与 `make build-parts` 同一读取路径，离线可用）取两块板 BOM；按 `config/env/default.yaml` 的参数（G7）和种子生成订单、工单（固定开工提前量与工期、分配到 2 条产线）、初始库存、少量在途采购单与运单。每条记录标记为模拟数据（spec §1.3）。
3. **查询与写入接口**（类 ERP，返回纯 dict）：查订单、工单、库存（含可用 = 在库 − 预留、在途）、采购单、运单、BOM、当前日。写入只有 `submit_purchase_order`（料号、数量、分销商、单价、幂等键）；同一幂等键重复提交返回同一张单、不重复下单。F03 不校验审批令牌（G2 由 F12/F21 在执行器一侧强制）；其他写入种类（如计划员改计划）由后续 Feature 按同一日志格式加入。
4. **快照、分叉、写入日志与崩溃恢复**（一次迁移 `0002_env`）：每日开盘（当日机制执行完、外部写入之前）存整状态快照（规范化 JSON + SHA-256），只写一次；写入先落 `env_write` 再作用于内存；恢复 = 最近快照 + 重放其后写入（进程死在推进与存快照之间时按确定性机制补推进）；分叉 = 把某日开盘快照复制为新 run 的起点；预演 = 只在内存载入快照。两张表只追加（触发器禁止改删）。存储抽象为接口，离线测试用内存实现，集成测试用 Postgres 实现。
5. **结果指标**（spec §4.6 环境侧三项）：停线天数、订单延期天数、采购成本。另两项（违规次数、打扰人工次数）的数据在 Session 事件日志里，由 F06 投影、F27 汇总，F03 不重复计算。

外加 `make sim-run SEED=…`：无 Agent 跑满 84 天，打印每日摘要与指标（即"什么都不做"基线的雏形，正式基线归 F04）。

## 不做什么
- 不做异常注入与情景 YAML（F04）、模拟人工（F05）、分销商报价（真实 API + 叠加注入归 F07/F04）。
- 不做案子、事件日志、Artifact（F06），不做审批令牌（F12），不做工具代理层 / MCP（F07）。
- 不建数据库权限规则给 Agent（F11）；新表不授予 `supplyagent_app` 任何权限。
- 不做排产、不提供任何改计划 / 改工单的写入（G8）。
- 不联网、不调用任何外部服务。

| # | 命令 | 通过条件 |
|---|---|---|
| 1 | `make check` | compile、lint、离线测试全绿；离线测试覆盖：同种子两次生成与推进结果哈希一致、不同种子不同；缺料停线后到货当日开工；延期天数按天累计；幂等键不重复下单；内存存储的崩溃恢复与分叉 |

| 4 | `make sim-run SEED=42` 两次 | 输出逐字相同；两块板都有订单与工单，指标非全零（说明无 Agent 时环境自然产生缺料） |

## 风险与默认值（设计分歧时再问）
- 生产节拍简化为"工单工期 N 天、一次性领料、完工一次性交付"，产能按产线串行；够给 Harness 施压即可（spec §4 开头"大致符合现实"）。
- 预留每日按开工日先后全量重算，不做手工锁定。
- 快照在"日开盘"存（实现时由原定"日收盘"改定）：每份只写一次、不更新；分叉点天然落在"同一局面、谁都还没动手"。某日中途崩溃 = 当日开盘快照 + 重放当日写入。
