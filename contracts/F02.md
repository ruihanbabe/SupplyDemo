## 目标
第二块板 bms-c1 与 hackrf-one 同等入库：原理图进只读原始层、经 MANIFEST 校验，`make build-parts` 后 `hw_part` 中两块板按 `project_id` 并存；再为两块板整理板级上下文。用于跨板迁移实验与 Eval 留出集（spec §1.1）。

## 分两步推进
1. **原理图入库**（本 Contract 当前覆盖的部分）。
2. **板级上下文**（spec §1.3"README 人工整理成结构化字段"）：第 1 步验收后单独给方案，经确认后补进本 Contract，再开工。

## 第 1 步做什么
1. 从 git 历史 `8342d20^` 恢复 `data/hardware/raw/bms-c1/`（7 个文件 + MANIFEST，已按电子元件规则裁剪过），恢复后设为只读，与 hackrf 一致。
2. `config/knowledge/sources.yaml` 加回 bms-c1 条目（内容取自同一历史版本）。
3. 测试：离线检查的板列表加入 bms-c1（MANIFEST 一致、位号全部来自实例表、原始层只读）；集成测试 `build_all` 的期望改为两块板各自的料号数。
4. 不改 `src/` 代码：`hw_part` 已按 `project_id` 区分。

## 不做什么

## 第 2 步：板级文档存档（用户 2026-09-29 确认方案 A）
板级资料不做人工结构化：README 原文存进原始层作为证据，需要时由文档工具调取（与 datasheet 共用，spec §6），判断交给工程师。

**做什么**
1. `sources.yaml` 每块板加 `docs` 列表，本期只有 README：hackrf 为根目录 `Readme.md` 与板目录 `hardware/hackrf-one/README`（板级说明在后者），bms-c1 为根目录 `README.md`。
2. `knowledge.fetch` 新增只拉文档的入口：按钉死的 commit 取文件、校验 git blob、只读落盘到 `data/hardware/raw/<板>/`（保持仓库内相对路径），追加进该板已有 MANIFEST；不重拉、不裁剪原理图。`fetch-hardware` 的文件筛选同时认 `docs`，重拉时不丢文档。
3. Makefile 新增 `fetch-docs` 目标。
4. 测试：登记的文档都在 MANIFEST 中且哈希一致（沿用现有 MANIFEST / 只读检查）。

**不做**：文档工具（目录 / 检索 / 读页）归 M2 datasheet 知识库 Feature；不拉 `docs/` 目录；不做摘要或结构化字段。
