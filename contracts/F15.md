# F15 Contract：异常处理与恢复

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度② ｜ 里程碑：M3 ｜ spec：§5.8 ｜ 依赖：F07、F09、F21

## 目标
每种失败只有一条由代码固定的处置路径（自动重试 / 降级 / 交回编排者 / 升级给人），是否重试不由模型决定；进程崩溃后重放恢复，**不重复下单**。

## 做什么（`src/resilience/`，配置 `config/resilience.yaml`）
1. **重试与退避**（`retry.py`）：限流、超时、上游错误最多自动重试 2 次，按真实时间指数退避（基数与倍数在配置；睡眠函数可注入，测试不真睡）。参数错误、查不到、格式异常、无权限、门控拒绝不重试。
2. **熔断**（`breaker.py`）：同一上游（分销商、模型端点）重试后仍失败计 1 次，连续 3 次即熔断 5 分钟（真实时间）；状态放 KV（Redis，TTL 到期自动恢复）；熔断期间直接返回"暂不可用、可重试"，不发请求；成功一次清零计数。
3. **接入工具代理层**：配额 → 调用两步放进重试循环（测试注入挂点也在循环内，F18 可注入"首次超时"）；熔断中的提供方按部分成功处理（全部熔断则返回上游错误、可重试）；分销商 Server 对单家失败只记下该家（部分成功 + 计入该家熔断），整批失败才重试。`tool_call` 事件记尝试次数与熔断中的来源。
4. **接入模型适配层**：端点传输失败（限流、超时、上游）同样重试 + 熔断；最终失败抛 `EndpointUnavailable`（`ModelUnavailable` 子类）。执行者循环捕获它：子 Agent 交回"未完成"、编排者结束本段并记原因（交回调用者，不升级）；未接入重试组件时原样上抛（F09 崩溃测试不变）。
5. **意图 / 完成两步写**：提交采购单先写 `po_submit_intent`（幂等键 = 案子 + 草稿版本 + 内容哈希）→ 写环境 → 写 `po_submitted`；环境拒绝写入记 `po_submit_failed` 并按门控拒绝反馈（修正 F21 注释与实现不符）。`recover_pending_writes(session, env)`：有意图无完成时按幂等键向环境重发（环境按幂等键去重：已存在即返回原单）→ 补记完成（标 `recovered`）。
6. **补偿**：已提交采购单所依据的草稿之后失效（如替代料验证失效）→ 不自动撤单，F14 强制升级新增规则 `post_submit_invalidation` 升级给人。
7. **部分成功**：比价缺来源时只要有效报价满足数量，门控允许据此下草稿，决策记录缺失来源（F21 已有，本 Feature 补测试）。
8. **子 Agent 未完成后重派**：`dispatch_task` 发现本案同一执行者同一任务说明此前未完成 → 标 `redispatch_of`，案子预算把重派计为一次重规划。
9. **消融开关**：`auto_retry`（false 时不重试）、`circuit_breaker`（false 时不熔断）。两步写与幂等是不重复下单的底线，不设开关。

## 不做什么
- 人工超时（spec §5.8 本期不做）；F18 的回放模式与分叉；自动撤单。
