# F13 Contract：字段级污点追踪与汇点检查

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度 ｜ 里程碑：M2 ｜ spec：§5.5 污点追踪、G4、G6、B1 ｜ 依赖：F06、F11

## 目标
安全不靠模型注意力（spec §5.5）：Artifact 的每个字段由代码按来源打标，汇点由代码检查；标签是 Harness 数据层元数据，默认不给模型看。注入即使骗过模型，被污染的字段也进不了采购单、Policy 打分、系统结论和长期记忆。

## 做什么（`src/taint/`，配置 `config/taint.yaml`）
1. **标签与存放**：四种标签：可信 `trusted`、外部结构化 `external`、不可信文本 `untrusted`、已校验 `verified`。存在 Artifact `meta.taint`：`{字段路径: 标签}`，路径用 `.` 分层、`[]` 表示任意列表元素，`*` 为缺省；查询取最长匹配前缀。合并规则取最弱（untrusted < external < trusted = verified）。
2. **按来源自动打标**（产出方写入，不由模型决定）：
   - F21 代码组件：`ImpactReport` 全部可信；`SourcingQuote` 的报价行为外部结构化，代码推算的字段可信；需求来自 `ImpactReport` 时继承其标签，来自编排者 `params` 时料号在环境目录中可查则已校验、否则不可信，**数量为不可信**（LLM 给出的数值，G4）；`ProcurementDecision` 的选中报价继承 SourcingQuote 标签，打分为可信。
   - F09 LLM 子 Agent 的产出一律不可信（conservative 缺省）；`mark_verified()` 供 F23 引用校验通过后去污（产出新版本）。
   - `PODraft` 字段继承自被引用 Decision 的对应字段。
3. **汇点检查**（`sinks.py`，规则在配置）：
   - **采购单内容**：建草稿时料号、数量、供应商、单价只能取可信 / 外部结构化 / 已校验字段，否则拒绝并写 `gate_rejected`（原因写明字段与标签）。
   - **Policy 打分**：读入的打分字段（单价、库存、到货日、分销商）不得为不可信，否则决策以"未完成"返回。
   - **给人看的文本**：F16 摘要里不可信字段只能放进标明来源的引用块（取代 F16 的 `external_fields` 手工清单，旧字段仍兼容）。
   - **长期记忆写入**：只接受带 H1 确认记录的条目，条目中不可信文本只能在引用块里——本 Feature 只提供检查函数与测试，写入接口归 F20。
   - **出站请求**：从不可信内容读出的网址须过 F11 出站白名单，否则拒绝——提供检查函数，真实下载归 F19。
4. **疑似指令检测**（B1 兜底）：代理层对交付给模型的文本字段按配置正则检测（如"忽略以上指令""ignore previous instructions""你现在是"），命中加警告"疑似指令文本，已作为数据处理"并在 `tool_call` 事件记 `injection_suspected`，供 Eval 统计；不改数据。
5. **标签不进模型上下文**：上下文组装不输出 `meta`；测试断言编排者 / 子 Agent 收到的文本里没有标签。
6. **消融开关**：`taint_tracking`——false 时照常打标，但汇点不拦、不做疑似指令检测（Eval 对比注入用例的拦截率）。

## 不做什么
- datasheet 引用校验本身（F23）、知识库 B 写入接口（F20）、真实下载（F19）、审批令牌与证据门控（F12）。
- 对工具返回（交给模型的原始数据）逐字段打标：它不落成 Artifact，模型产出的一切本来就按不可信处理。
