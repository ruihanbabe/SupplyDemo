# F45 Contract：商机情报问答的完整只读链路

状态：2026-10-23 用户确认开始开发；代码已实现，等待用户验收；业务库迁移尚未应用。
引用：spec §0.3、§2.5、§2.6、§3；业务目标见 business-logic.md BL01。

## 本单元

用户选择有权限的商机并提问，HTTP 幂等排队，Worker 并行调查客户事实和组织知识，必要时查询绑定的供应事实；诊断节点根据实际问题和前序结果回答。工作台展示运行状态、答案、引用、未知和冲突。所有工具按提问者身份读取，不借 Worker 身份扩大资料权限。

追加 0024：私有 intelligence_request 绑定提问者/商机/Run；intelligence_attempt 按 Job generation、角色、invocation 保存实际输入快照与结构化输出；intelligence_observation 按实际工具调用保存内容与哈希。它们不复制全量业务历史，也不把问题和原始结果写入组织级公开 Trace。写入检查活动 Job lease 与 generation；重试重新调查，保留各批次，不声称从 Pi 内部指令恢复。读取限原提问者且重验商机权限；Worker 可处理记录。

模型上下文由当前问题、角色约束、明确前序结果和精确 R0 工具集组成。工具正文作为证据，不作为系统指令。引用检查验证实际 Observation 的同 Run 身份/哈希；知识引用额外重验当前 ACL/版本。该检查不等同语义审查，结果显式 needs_review。

## 范围之外

其他三个业务入口、CRM 写入/发送/转人工、完整对话追问、多 Agent 冲突裁决、长期 memory 治理、MCP/Skills 动态装载、语义 Judge、自动模型路由及付费真实调用均保留后续，不因本单元简化而取消。

## 验收

- HTTP 输入、幂等不同问题拒绝、跨组织/同组织他人及撤权读取拒绝。
- 真实 PostgreSQL 克隆库与锁定 Pi Replay 证明排队、并行前序、诊断、持久快照、引用和失败记录；不调用外部服务。
- Worker 重试保留 generation，过期 lease 不能接受输出。
- 前端 BFF 边界、lint/build；页面加载、空数据、运行中、结果和错误可辨，Replay 标签明确。
- make check；集成失败按本单元与已有 F41 草稿分别报告。

## 数据落点与时序

数据身份/输入/Observation/输出约定统一见 data-contract DC01–DC08；业务角色与工具分工见 business-logic BL03。0024 实现 request/attempt/observation；后续全 Case 料号与时间绑定见 F46，BOM/报价见 F47，Gateway 协议/交换关联见 F49/F50。

接单 → SQL Job → 并行角色 → 诊断 → 受控接受结果 → 当前权限/来源重验后读取。当前为固定模板；追问、动态计划、语义支持审查和裁决尚未实现。

组件准入：必要性是贯穿实际问题与输入/输出记录；复用 F35/F36/F40/F42 而不增加独立服务；代价为三张私有表和额外只读调查；收益通过端到端与隔离/恢复测试验证。消融开关 `SUPPLYAGENT_INTELLIGENCE_ENABLED=0` 仅暂停新请求，不破坏既有任务及读取。

## 中断后续验与共享权限修复
