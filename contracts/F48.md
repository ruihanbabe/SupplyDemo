本次明确修订旧 F48：SQL 保存准确过程摘要/已确认稳定记忆版本和来源；Mem0 是唯一有效记忆语义检索后端，保存发布检索投影及可选稳定候选加工。SQL 不另建一套有效记忆向量/全文检索；业务事实仍归领域服务。2026-10-27 按用户补充调整为通用过程摘要优先，稳定命题抽取按需使用，详见 BL09。后端主选 Mem0 OSS；失败翻转条件见 BL09，不并行安装其他框架。

## 范围、依赖与准入

范围包括默认通用过程摘要、按需稳定记忆、前后置准入、异步捕获/摘要/按需确认/发布、来源合并与版本替代、意图检索、引用/渐进读取、软忘记与硬删除、复盘/Dream、旧 memory.py 单一读取切换。短期消息/Working State/Compaction 由 F52 负责，F48 只对接其 MemoryPort 与来源提交 Interface。

开发顺序：F51 → F52 → F48；一次一个 Feature 和一个实施单元。F52 可使用空 MemoryPort 独立验收，避免 F48↔F52 循环依赖。F48 的受控后台后端测试不要求真实客户数据、真实渠道或付费模型；实时服务调用另按 G5 授权。

不实现审批/发送、业务事实写回、动态 Planner、其他记忆框架并存、权限由模型决定或从 Pi session 恢复。记忆确认命令不签发业务动作授权；无模型侧自动调用的通用 memory.write 工具。

必要性：偏好和过程复用需要多来源、时序及审阅，现有单来源状态模型不足。最小路径先交付带来源的过程摘要跨会话检索闭环，兼容显式个人偏好命令；不能用这一切片删除后续实体/过程/巩固目标。新增成本为 Mem0/embedding/存储与治理模型，不新增 Agent 编排框架；复用现有 PostgreSQL Job、Trace、领域权限和 F52 会话。可关闭新加工、注入与 Dream，保留已提交来源和后台进度，不能恢复已删除内容。

## 专项验收矩阵

- 摘要：同一通用策略覆盖四场景，保留否定/时间/条件/理由/未决事项；过程摘要不强制结构化业务字段，自动可检索仍只属历史参考；Context 压缩摘要不能直接冒充完整长期来源。
- 准入：凭证/敏感信息在任何提取或 embedding 前过滤；恶意工具/文档不能改规则；synthetic 与真实隔离；助手推测不变已确认事实。
- ADD-only：追加新内容版本、原子替代当前投影；来源边追加；相似度不等于同命题；冲突/时序/条件不丢失。原文、摘要和语义断言分别引用。
- 异步：source watermark/outbox 同事务；结束及时 commit；索引延迟可见；远端成功后崩溃先对账；旧 generation 不发布；无跨系统 exactly-once 声明。
- 检索：可信 tenant/原用户/对象预过滤在后端执行，未授权正文不进入 reranker；返回后重验；缓存命中仍受撤权/删除；限次扩搜与预算；依赖历史的问题在服务不可用时明确缺失。
- 删除：vector、candidate/active、history/messages/entity、SQL 正文、Context 派生与缓存逐目标验证；source 删除范围明确，备份待清除单独显示；不能只测 search 不命中。
- 成本：提取、embedding、重排、巩固单独计量；不得使用 SDK 默认外部模型/Key；无授权请求、未知 usage 和超预算不得当零费用成功。
- 回归：F36 旧生命周期、F45/F49/F50 现有产物/权限保持；无静默双读/双写权威，旧状态显式映射而非强制确认。
