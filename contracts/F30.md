# F30 Contract：v0.5 重基线与既有能力兼容审计

> 状态：已写，待用户验收（2026-10-09）｜类型：最小｜里程碑：M0｜spec：§0.4、§3、§5

## 目标

把 F01–F29 的已有实现逐项映射到 v0.5 产品边界，明确“可原样复用 / 需适配 / 仅测试后端 / 缺失”，不改写历史验证结论，也不把单租户模拟能力误报为多租户生产能力。

## 2026-10-10 架构重基线补充

兼容审计的产品目标变为 v0.5：Next.js/TypeScript 只承担薄前端/BFF；Python API/Worker/Harness 是产品服务端；Node 仅能作为无状态 Pi JSONL sidecar。2026-10-12 已删除须由 Python 重做的 Next 服务实现；F31–F42 Contract 只描述当前所有权与待实现边界。历史资产分类、F05 `eval_only` 结论和禁止直接暴露 `simenv` 的结论保持不变。

## 做什么

1. 建立一张唯一兼容矩阵：图中每个能力、现有模块/测试、适配缺口、目标 Feature、复验命令和结论。
2. 审核至少六类边界：组织上下文、RLS、API/前端、Worker 队列、凭证/BYOK、渠道副作用。
3. 将现有 F03–F23 按“业务内核、Harness、测试/模拟后端”分类；记录不可直接暴露给模型或 API 的内部接口。
4. 只更新文档、features 状态说明和 HANDOFF；不改业务代码、迁移或已有 Contract 的历史验收记录。
5. 审计结果只写入 `docs/audits/F30-v04-compatibility.md`；该文件是 F30 的唯一兼容矩阵，其他文档只链接或概述其结论。

## 不做什么

- 不为兼容审计补写多租户、Web、队列或渠道代码。
- 不把 mock/回放后端写成真实 Provider 或真实渠道已经接通。
