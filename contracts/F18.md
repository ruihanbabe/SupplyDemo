# F18 Contract：测试注入、回放与分叉

> 状态：已写，按用户 2026-09-29 授权直接实现、事后统一验收 ｜ 类型：深度① ｜ 里程碑：M3 ｜ spec：§5.12、§4.6 ｜ 依赖：F03、F07、F08、F09

## 目标
任何一次运行都能被稳定触发、完整重现、互相比较（spec §5.12，§0.2 可复现）。

## 做什么（`src/replay/`）
1. **注入计划 `FaultPlan`**（`faults.py`）：从情景 YAML 的 `faults:` 段（或字典）读规则，每条规则 = 挂点 + 匹配条件（工具 / 端点 / 分销商 / 模拟日 / 第 N 次）+ 注入类型：
   - 工具代理层：超时、限流、上游错误、返回格式异常（经 F07 `faults` 挂点，在 F15 重试循环内逐次判断）；
   - 模型适配层：输出不合 Schema、超时（包一层传输）；
   - Runtime：在指定点杀进程（F15 采购执行器的 `after_intent` 点："意图之后、调用环境之前"）。
   每次注入写 `fault_injected` 事件（挂点、类型、命中的规则），标明测试注入。
2. **回放模式**（`modes.py`）：
   - 实时：现状（真实 / 固定样例后端，响应留档）。
   - 数据回放：`ArchiveReplay` 以源运行的 `tool_call` 事件与留档为准，外部来源工具按（工具, 参数）第 N 次调用取原始返回，不调后端、不扣配额、不熔断；留档缺失直接抛 `ReplayMissing`，不回退真实调用。模型照常调用。
   - 全回放：另加 `ReplayTransport`，按端点依次回放源运行 `llm_call` 记录的响应（记录的失败按原类型重抛）；请求哈希与原记录不一致抛 `ReplayDiverged`。同一运行号重跑时事件日志哈希链与原运行一致。
3. **分叉重跑**（`fork.py`）：`fork_at_wake(源 Session, 源环境存储, 唤醒事件号, 新运行号)` 只允许在 `case_woken` 事件处分叉：复制该事件之前的事件日志（序号不变、重新成链）与 Artifact（含依赖），其后写 `forked_from`；环境取当日开盘快照（F03 `Environment.load(..., into=...)`）并补上当天分叉点之前已完成的写入。分叉点之后由调用方用新条件（提示词、模型、配置）跑；此前的留档记录可按源运行号读取。
4. **运行清单**（`manifest.py`）：代码 commit、模型 ID 与端点、提示词 / Skill / 比对清单 / 配置文件哈希、Policy 版本、配置快照、种子（环境、情景、注入）、留档源运行；写 `run_manifest` 事件；`diff_manifests()` 列出两份清单的差异。

## 不做什么
- 情景 YAML 本体与 A/B 类业务异常（F04）；Eval 运行器与比较报表（F27）；Web 时间线并排展示（F26）。
- 原运行有配额 / 限流造成的部分成功时，数据回放按留档里的原始数据交付，但"某来源不可用"的警告不再重现（事件会不同，全回放哈希比对以没有这类情况的运行为准）。
