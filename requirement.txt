# SupplyAgent 依赖与环境台账

> **文档契约** · 类型：规则层 · 读取：准备环境、增删依赖或排查版本问题时按节读
> 更新：安装、升级、删除任何依赖后由 Codex 即时写入，须同时填日期、原因与验证
> 独占：项目直接依赖清单、组件版本台账、依赖变更记录、明确排除的依赖及其理由
> 不收录：服务可用性的验证状态（见 `PROGRESS.md`）、命令实现（见 `Makefile`）、服务拓扑（见 `compose.yaml`）、环境变量清单（见 `.env.example`）、决策理由（见 `DECISIONS.md`）

本文记录「项目声明要用什么」与「本机实际装了什么」。**机器真相以 `requirements.lock.txt` 为准**（由 `make freeze` 生成）；本文承担人工审计视角的说明与取舍理由，不替代锁文件。

开发环境已于 2026-09-14 迁至本地，借用的 GPU 服务器不再是默认环境（见 `DECISIONS.md` D18）。

## 运行时

| 项目 | 版本 | 说明 |
|---|---|---|
| 宿主机 | MacBook Pro 2020，Intel i5-1038NG7，32 GB | x86_64，macOS 15.7.9 |
| Python | 3.11.15 | Homebrew `python@3.11`，路径 `/usr/local/opt/python@3.11/bin/python3.11` |
| 虚拟环境 | 项目根 `.venv` | 由 `make setup` 创建；Makefile 内部一律用 `.venv/bin/python`，不依赖是否已激活 |
| 计算资源 | 4 核 8 线程 / 32 GB | **本地不跑任何模型推理**，LLM 全部外部 API 调用，无 GPU 需求 |

Homebrew 自 2026-08 起不再为 Intel macOS 提供预编译包，`brew install` 会退化为源码编译。因此容器运行时与 CLI 均改用官方静态二进制安装，不经 brew。

## 容器与服务组件

| 能力 | 版本 | 运行方式 |
|---|---|---|
| Docker CE / CLI | 29.7.1 | 官方静态二进制装于 `/usr/local/bin/docker`，非 brew |

PostgreSQL 与 Redis 版本刻意对齐此前服务器上的版本，以便将来若启用远端环境时行为一致（见 D18 约束）。端口不得改成 `0.0.0.0` 或无认证 TCP 监听。

## 明确排除的依赖

以下均来自此前项目的环境，**不进入 SupplyAgent 的依赖清单**：

| 包 | 排除理由 |
|---|---|
| `torch`、`transformers`、`sentence-transformers`、`FlagEmbedding` | 本地模型推理栈。MVP 无 RAG／向量检索（D12），LLM 全外部调用，装了纯占空间；Intel Mac 无 CUDA，CPU 推理也不可用 |
| `qdrant-client` 及任何向量库 | D12 已移除向量检索；若将来重新引入，按 D11 用 PostgreSQL 扩展而非独立向量库 |
| `ragas`、`datasets` | 评测栈，且会连带拖入 LangChain 与 torch。EV 用例的判定由独立断言实现（见 `docs/product/acceptance-cases.md` §1），不依赖该框架 |
| `langchain`、`langchain-openai` | 不默认绑定特定编排框架 |
| `cn2an` | 中文数字解析，属此前项目的法规场景需求，本项目无此需求 |

## 依赖维护约定

1. 直接依赖、实际版本和变更原因统一记录在本文件；机器真相以 `requirements.lock.txt` 为准。
2. 每次安装、升级或删除包，同步更新本文件的日期、原因和验证结果，并重跑 `make freeze`。
3. 需要可复现锁定时由 `make freeze` 生成，不手工编辑锁文件。
4. 禁止把 API Key、凭据或本地绝对路径写入依赖台账或锁文件。
5. 新增依赖前先确认它不在「明确排除」表中；确需引入被排除项，先在 `DECISIONS.md` 记录推翻理由。
